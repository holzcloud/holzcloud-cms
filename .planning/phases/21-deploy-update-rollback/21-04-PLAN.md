<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| snapshot file to live database | a restore replaces the live database with a file from disk |
| old binary to newer schema | the older program runs against data it does not fully know |
| restored users, sessions and keys tables | a rollback brings back credential state from before the update |
| scratch output to committed documents | negative-case output includes order rows and journal lines |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-13 | Tampering | restoring a stale or foreign database over the live one | high | mitigate | only the snapshot the service itself wrote (newest by `ls -t`, shown first with `ls -l`); the migrated database is moved aside as holzcloud.sqlite.after-update so the rollback can be undone; `integrity` ok asserted after restart |
| T-21-14 | Tampering | replacing the database file under a live write-ahead log corrupts it | high | mitigate | the service is stopped and the -wal and -shm files are removed before the copy; the Rolling back block and the harness play exactly that order; integrity asserted |
| T-21-15 | Elevation of Privilege | credentials changed after the update come back with the snapshot (old passwords, revived sessions, revoked API keys) | medium | mitigate | the Rolling back section says so and tells the operator to re-apply the changes and restart; the comparison records the users, sessions and keys counts of the restored state |
| T-21-16 | Elevation of Privilege | restored database root-owned or world-readable | medium | mitigate | restore with `sudo -u holzcloud cp`; `rollback.txt` asserts owner holzcloud and mode 600; the set-aside copy keeps mode 600 and is called out as holding password hashes |
| T-21-17 | Tampering | an older binary silently accepts a newer schema and corrupts later writes | medium | mitigate | the limit is stated first in the section and backed by the played negative case; the harness leaves the post-update state intact afterwards |
| T-21-18 | Information Disclosure | negative-case output includes test order data and journal lines | low | accept | throwaway container, test data only, no credential rows; leak_check and the pattern scans still run |
| T-21-SC | Tampering | package installs | low | accept | no npm, pip or cargo packages are added by this plan |
</threat_model>
