## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service database to scratch output | comparison output could carry rows of credential tables |
| snapshot and backup files on disk | they hold password hashes, session data and the CSRF key |
| the old tag build | the old binary comes from a named git ref and Go modules fetched at build time |
| service start after replacement | a binary that fails to migrate leaves the unit in a restart loop |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-21-09 | Information Disclosure | the complete state, compare and attach output could dump rows or columns of users or sessions (password hashes, tokens, addresses) | high | mitigate | counts and content hashes only; never a select on credential tables; `leak_check` plus a verify grep for a password-hash prefix, the login password and key-shaped strings |
| T-21-10 | Information Disclosure | snapshot or backup readable by other users | medium | mitigate | `attach-s1.txt` asserts the snapshot is 0600 and owned by the service user and the backup directory is 700; observed values are recorded |
| T-21-11 | Denial of Service | an update that fails to start leaves a restart loop | medium | mitigate | the Updating section names the journal check and StartLimitBurst and sends the operator to Recovery; the harness asserts /readyz after the start |
| T-21-12 | Tampering | the old tag build pulls Go modules at build time | low | accept | modules are checked against the old tag's own go.sum; the binary runs only in a throwaway container |
