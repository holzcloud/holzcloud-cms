<objective>
The standing gate, and the half of it no test can hold.

Two things close this phase. The first is mechanical: `go run ./tools/i18n` must
report `0 offen, 0 verwaist` on all four catalogues it writes. The second is not:
everything a person can see has to have been **seen**, in a browser, once.

The browser pass is where this project's real defects have been caught. Phase 8's
whole gate was a `layoutPageNames` entry that every test passed without —
`internal/web/render.go:46` is a hand-maintained slice of names, and a template
missing from it renders as a bare fragment with no navigation, no flash area and
no CSRF body attribute. This phase adds four templates to it. Nothing in
`go test ./...` looks at a rendered layout.

**And the pass runs after the code-review fix round, not before.** In both Phase
7 and Phase 8 the verifier found user-visible changes that landed *after* the
pass had already been signed off, which makes the signature worthless. This plan
is last for that reason, and task 2 carries the precondition explicitly: do not
drive the browser until the review fixes for this phase are committed.

Both import paths are driven — a **new** website and an **existing** one. The
roadmap's planning notes require it in as many words, and the existing-website
path is this phase's deliberate departure from `wordpress.go:15-19`'s rule that
an importer always creates a new website.

Purpose: QUAL-01 and QUAL-02 for phase 9, criterion 6, and one last measurement
of every counting gate against the finished tree.
Output: five catalogues and a driven browser session with evidence.
</objective>

**never deletes one** — reworded German leaves an orphan behind and it has to be
removed by hand.

`fr-CH.json` and `it-CH.json` are read-only to the tool and hand-maintained. They
must come out of this task unchanged, and a verify gate asserts it.

Commit the catalogues on their own, touching nothing else, the way phase 7 and
phase 8 both did.
