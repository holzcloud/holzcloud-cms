**1. The head comment (`internal/admin/csvimport.go`), before any code.**

`media_crop.go:14-24` is the model: a paragraph block at the top of the file
explaining why the shape is what it is, written for the reader who arrives in a
year. Say all five of these, because every one of them is a decision rather than
a transcription:

- **There is no multi-screen wizard anywhere else in this tree.** The two
  half-analogs are named and so is what was taken from each:
  `twofactor.go:184-201`'s re-render-with-the-state-re-fetched for a rejected
  mapping, `confirm.go:27-73`'s one-handler-two-verbs. **`twofactor.go:154`'s
  keying on the user id is deliberately dropped**: keyed that way a second upload
  would silently destroy the first.
- **The token is a path segment, screen 2 is a GET, screens 3 and 4 are POSTs.**
  The GET so the mapping is bookmarkable and `?zeile=N` steps the sample row
  without a POST; the POSTs because they are actions and screen 4 is not
  repeatable by a refresh.
- **A swept token renders a named expiry screen and not a 404.** The operator did
  nothing wrong and a 404 says they did.
- **The routes are `/admin/csv-import/{token}` and not
  `/admin/websites/import-csv/{token}`**, and the sentence says why in one line:
  the second conflicts with `/admin/websites/{id}/pages` under Go 1.22's
  `ServeMux` and panics `newRouter` at startup. Screen 1 stays at
  `POST /admin/websites/import-csv` beside its two siblings.
- **An import may target an existing website**, which is a deliberate departure
  from `wordpress.go:15-19`'s stated rule that an importer always creates a new
  one. That rule's own reason — every collision needs an answer — is answered
  here by screen 1's update-or-skip choice plus the dry run. `ROADMAP.md`'s
  planning notes require this departure to be written into the plan as a
  decision; this comment is where it lands in the code.

**2. The data structs.** `media_crop.go:26-44`'s shape — `web.LayoutData`
embedded, `web.FormState` embedded too on a screen that can be rejected
(`confirm.go:18-23`), then per-screen members each with a comment saying why the

**3. `HandleCSVImport` — screen 1 (`POST /admin/websites/import-csv`).**

`r.Body = http.MaxBytesReader(w, r.Body, 10<<20)` first, with the comment copied
from `wordpress.go:23-25` and its reason swapped: a CSV is text and ten megabytes
is more than any table an operator will hand-maintain, and little enough for a
small server (D-08).

`r.FormFile("csv")`; the failure arm is a flash plus redirect to
`/admin/websites`, exactly `wordpress.go:28-32` — a file that is missing or over
the cap is not a form-validation error and there is nothing typed to hand back.

Read the bytes, then in this order:

- `csv.PruefeBytes` — three distinguishable refusals, three distinguishable
  flashes: nothing was uploaded; the file is only a byte-order mark; the file
  contains a NUL byte and is not a CSV (D-15, IMP-09 empty).
- `csv.Neu` — a file with no header row at all is refused here with its own
  message. A header *cell* that is empty is **not** a refusal; that column is
  offered as „Spalte N" on the mapping screen (IMP-01 empty).

Then the target, from the panel: `ziel` is `neu` or `bestehend`; for `bestehend`
fetch the website through `h.domains` and refuse an unknown id; for `neu` take
the name (falling back to the file name, then to a fixed name, the way
`wordpress.go:40-46` cascades). `kollision` is `uebergehen` or `aktualisieren`
and anything else is `uebergehen`, because the safe direction is the one that
writes less.

**The website is not created here.** It is created by screen 4, after the dry
run, so an operator who abandons the wizard does not leave an empty website
behind. Say that in a comment — it is the difference between this importer and
`wordpress.go:48`, which creates the website before it reads a single item.

`h.csvImports.Stage(...)`, then `h.redirect(w, r, "/admin/csv-import/"+token)`.
A 303 and not a render, so a refresh of screen 2 is a GET.

**4. `ablage` — one helper, every token-bearing screen.**

```
func (h *Handler) ablage(w http.ResponseWriter, r *http.Request) (*csvimport.Ablage, bool, error)
```

It reads `r.PathValue("token")` and the current user, calls
`h.csvImports.Holen`, and maps the two sentinel errors:
`errors.Is(err, csvimport.ErrFremd)` → `http.NotFound`, returns `false`;
`errors.Is(err, csvimport.ErrAbgelaufen)` → render `csv_abgelaufen` with 200,
returns `false`. Every screen calls this and none of them re-implements it —
plan 09-05 adds two more callers and must not have to remember the rule. Its doc
comment carries the ordering discipline from `sharelink.go:79-82` in this phase's
own terms: an upload that was swept and one that is somebody else's get different
answers, honestly, because the first is not the operator's fault.

**5. `HandleCSVMapping` — screen 2 (`GET /admin/csv-import/{token}`).**

Re-read the staged bytes and re-check the target (D-29, IMP-04 concurrency): the
website may have been deleted between screen 1 and now, in which case the wizard
ends with a message rather than a nil dereference; the field definitions are
re-read here and again at the dry run and again at the write, so a mapping naming
a definition that no longer exists is reported and its column falls back to
unmapped.

Build the mapping with `csvimport.Automatisch(leser.Kopf(), defs)`, and the
column list with `csvimport.Spalten` — **in the file's column order, always**
(IMP-01 ordering), because it is the order the operator sees in their spreadsheet
and any other order makes the sample row beside it unreadable.

The sample row (IMP-08): read forward through `csv.Leser` to the requested index.
`?zeile=` is a 1-based **data-row** index; clamp it to `[1, n]` rather than
refusing — it is a hand-typed number, not an attack (IMP-08 adjacency). The
number shown to the person is `csv.Zeilennummer(index-1)`, the same helper the
report uses, so „Zeile 2" is the same row on both screens (IMP-08 ordering,
D-26). At the first row there is **no** previous control and at the last there is
**no** next control — absent, not disabled, because a disabled link is a control
a keyboard user still lands on. With no data rows at all, `KeineZeilen` is true
and the template says so in a sentence (IMP-08 empty).

Render with `web.RenderAdmin(w, h.templates, r, "csv_mapping", data)`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| an uploaded file → the server's memory and the staging table | 10 MB of somebody else's bytes, arriving over a multipart POST. |
| a token in a path segment → a staged upload | The address is typed, copied, bookmarked and logged. |
| `?zeile=` in a query string → an index into a file | A hand-typed number reaching a slice. |
| an operator's field labels → a CSV opened in Excel | A label beginning `=` is a formula when the file is opened. |
| a new route → the authorization chain | `requireAdmin` and the `adminOnly` table are two separate acts, and only the first one is in `main.go`. |
