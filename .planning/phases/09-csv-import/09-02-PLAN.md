<objective>
The file has to survive four screens, and a server cannot fill a file input.

That single fact is what overturned the roadmap's „re-submit the file with the
mapping" (D-01): `<input type="file">`'s value is not settable from markup, a
form POST loads a new document, and IMP-08's „one real row, navigable to the
next" would therefore demand a fresh file pick on every arrow click. The note's
actual concern — *do not put the parsed table in the session* — is honoured
exactly here: the SCS session row gains nothing, and what is staged is the **raw
bytes**, never a parsed table.

This plan builds the medium. A `csv_imports` table rather than a file under
`data/`: one place to delete from, `ON DELETE CASCADE` from `users` so an account
deletion cannot leave orphans, and a sweep that is one `DELETE` rather than a
directory walk that has to tell a stale staging file from a live one.

Two things here are consciously *not* copied from their analogs, and both would
be silent defects:

- `internal/user/token.go:59-62` deletes the previous token for the same user so
  an old link stops working. A staging token must **not**: an admin with two
  browser tabs would lose the first import.
- `internal/admin/twofactor.go:154` keys its half-finished state on the **user
  id**. Keyed the same way, a second CSV upload would silently destroy the first.

`internal/csvimport` is a second package beside a pure `internal/csv` (D-35).
The counter-evidence is named so this is not read as an oversight: `internal/shop`
puts `cart.go` and `pricing.go` in one package and is none the worse for it.
Purity wins here because D-03 spends it — plan 09-01's checklist is testable with
no `db.Open`, and merging the store in would end that.

Purpose: the staging that makes IMP-05 true and IMP-08 buildable at all.
Output: migration `00049`, the store, the prune job, and one line in `NewHandler`.
</objective>

**1. The migration (`internal/db/migrations/00049_csv_imports.sql`).**

Migrations currently run to `00048_snippet_group_namespace.sql`; `00049` is the
next free number, and 48 files exist. Do not edit any file below it.

German comments throughout, in the register `00042` sets. Head comment, in
`00042:1-12`'s voice: what the table is for and what goes wrong without it. Say
the three things a later reader needs — that a CSV cannot ride in the SCS session
because sessions live in SQLite and a 2 MB row there is a bad day; that a server
cannot fill a file input, so screens 2 to 4 carry a token and no file field; and
that what is stored is the **raw bytes**, never a parsed table.

```
CREATE TABLE csv_imports (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    token_hash   TEXT    NOT NULL UNIQUE,
    user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    website_id   INTEGER REFERENCES websites(id) ON DELETE SET NULL,
    website_name TEXT    NOT NULL DEFAULT '',
    modus        TEXT    NOT NULL CHECK (modus IN ('neu', 'bestehend')),
    kollision    TEXT    NOT NULL DEFAULT 'uebergehen'
                         CHECK (kollision IN ('uebergehen', 'aktualisieren')),
    dateiname    TEXT    NOT NULL DEFAULT '',
    daten        BLOB    NOT NULL,
    erstellt_am  TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))
) STRICT;

CREATE INDEX idx_csv_imports_alter ON csv_imports(erstellt_am);
```

Per-column German paragraphs, and three of them carry a decision rather than a
description:

- `user_id` — **this is the one place the cascade is not from `websites`.** Say
  so explicitly and name `00012` as the precedent, because a reader who has seen
  the other forty-seven migrations will otherwise read the next line as a
  mistake. A staged upload belongs to the person who uploaded it: that is what
  makes „one admin cannot resume another's half-finished import" a database fact
  rather than a handler convention, and it is why deleting an account cannot
  leave an orphan holding 10 MB.
- `website_id` — nullable **on purpose**, and the sentence says why: an import
  that is creating a new website has no website yet. `ON DELETE SET NULL` and not
  `CASCADE`, because a target website deleted mid-wizard must end the wizard with
  a message (IMP-04 concurrency, D-29) and not with the operator's file
  disappearing from under them.
- `daten BLOB` — the raw upload, capped at 10 MB by the handler before it ever
  reaches here. SQLite carries a 10 MB BLOB without complaint, it is written once
  and read three times, and `BLOB` is one of the five types `STRICT` admits.

The `+goose Down` half is `DROP INDEX IF EXISTS idx_csv_imports_alter;` then
`DROP TABLE IF EXISTS csv_imports;`. Nothing else — this migration creates and
does not alter, so its rollback cannot go one migration too far the way an
index-swap rollback can. Say that in one line, so the next person reading a
`Down` half in this directory knows why this one is two statements while
`00047`'s is six.

Add `TestMigration00049RunterUndRauf` to `internal/db/db_test.go` in the shape of
`TestMigration00047RunterUndRauf`, driving `migrationProvider` directly so the
`Down` half is actually exercised — nothing else in the tree runs it, which is
why it is the half that ships broken. Migrate up, insert a user and a website and
one `csv_imports` row, assert the row is there, run `Down` for version 49 and
assert the table is gone, then `Up` again and assert it is back and empty.

**2. The store (`internal/csvimport/store.go`).**

New package. Doc comment in the register of `internal/csv`'s: what it holds
(a staged upload between screen 1 and screen 4) and what it deliberately is not
(a parser — that is `internal/csv`, which stays pure so its hostile-file
checklist needs no database, D-35). Name the counter-evidence: `internal/shop`
puts a store and a pure calculator in one package; the split here is bought
deliberately with D-03.

```
type Ablage struct {
    ID          int64
    UserID      int64
    WebsiteID   int64   // 0 for an import that will create a website
    WebsiteName string
    Modus       string  // "neu" | "bestehend"
    Kollision   string  // "uebergehen" | "aktualisieren"
    Dateiname   string
    Daten       []byte
    ErstelltAm  time.Time
}
```

`ErrAbgelaufen` and `ErrFremd`, both `errors.New`, both with a doc comment
saying which screen answers them. **They are deliberately distinguishable**,
which is where this departs from `user.ErrTokenInvalid` (`token.go:28-31`), whose
whole point is that the three reasons are *not* told apart. The reason for the
departure: an operator whose own upload was swept did nothing wrong and a 404
says they did (D-33), while a token that is genuinely someone else's is a refusal
and must read as one. The cost is that a correct guess of a foreign token is
distinguishable from a wrong guess — carried as T-09-08 in the threat model
below, accepted on the ground that the token is 128 random bits.

`Stage(ctx context.Context, a Ablage) (string, error)` — mint `make([]byte, 16)`
through `crypto/rand.Read` (D-07: 128 bits, and `crypto/rand` is the tree's
single idiom — `token.go:49`, `shop/cart.go:145`, `web/logging.go:49`,
`totp/totp.go:50`), render with `hex.EncodeToString` (D-07's choice, matching
`web/logging.go:53` and `hashToken`), insert the row with the SHA-256 of the
token, return the token. **Do not** delete any previous row for this user. Put
`token.go:59-62`'s absence in a comment: that line exists so a superseded
invitation stops working, and copying it here would mean an admin with two
browser tabs loses the first import.

`Holen(ctx context.Context, token string, userID int64) (*Ablage, error)` —
`SELECT … WHERE token_hash = $1`. No row → `ErrAbgelaufen`. Row whose `UserID`
differs → `ErrFremd`. Otherwise the `Ablage`, with `website_id` scanned through
`COALESCE(website_id, 0)` so a NULL arrives as 0 the way the field store already
does it. Read pool.

`Loeschen(ctx context.Context, id int64) error` — one `DELETE`, write pool. Plan
09-05 calls it once the write has finished, so a browser refresh on the report
finds no token and lands on the expiry screen instead of importing the file a
second time.

`Prune(ctx context.Context, olderThan time.Duration) (int64, error)` — one
`DELETE … WHERE erstellt_am < $1`, returning `RowsAffected`, exactly
`PurgeExpiredTokens`' signature so the job body is three lines.

**No `BeginTx` anywhere in this package.** Every method is a single statement,
which is what makes that true rather than a rule anyone has to keep. IMP-10's
gate measures it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a staging token in a URL → 10 MB of somebody's uploaded file | The token is the only thing in the address, and the address is copyable, bookmarkable and logged. |
| one admin → another admin's staged upload | `requireAdmin` admits every administrator of the installation; it does not narrow which import is whose. |
| a staged row → the disk a backup is written to | The row holds the file and, unless the token is hashed, a resumable URL. |
| the sweep → an import in flight | A `DELETE` on a live row ends someone's work with no message. |
