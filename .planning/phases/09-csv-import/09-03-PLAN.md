<objective>
Everything between a parsed row and a `page.PageCreate`, and still not a screen
in sight.

Two decisions in this plan are the ones that go wrong silently if they are taken
by pattern-matching rather than by reading.

**The first is `janein`.** `field.Check` has **no** `KindBool` case — any
non-empty value passes — and both readers (`page_fields.go:281`,
`render.go:126`) treat truth as `value != "" && value != "0"`. So a cell reading
`nein` imports as **true**, through a validator that says the row is fine. The
importer must parse a closed vocabulary and report anything outside it (D-19).

**The second is the shape of a reason.** `09-CONTEXT.md` D-03 says to copy
`importWordPressItem`'s one-row-returns-a-reason-string signature, and D-32
overrides half of it: copy the *discipline* (empty means it worked), not the
*type*. Measured: `tools/i18n/main.go:53-65` collects the first string argument
of exactly eight named Go functions, so a sentence built with `fmt.Sprintf` and
appended to a report is invisible to the tool. `wordpress.go:68-84` is the proof
standing in the tree today — those warnings are hard-coded German and
`go run ./tools/i18n` reports `0 offen, 0 verwaist` anyway. Phase 9's report is
*entirely* such strings. Left as `Sprintf`, QUAL-01 would report green while the
whole report screen is German-only — the same class of hole as
`internal/field/field.go`'s untranslated rejection reasons. Twice is a pattern; a
third time would be a decision. So a verdict is a **code plus its arguments**,
and the sentence is a `{{tf}}` literal in a template.

Purpose: IMP-01's mapping, IMP-06's matching, IMP-02's single creation path,
IMP-04's update-or-skip, and IMP-10's no-transaction-across-rows.
Output: the mapping, the verdict type and the row function — all testable over a
real database with no `http.Request` anywhere.
</objective>

**`FaltKopf(header string) string` — the fold, in one place (D-17, D-28).** Strip
combining marks, then `field.SlugifyKey`. Three lines and `unicode` only:

```
func FaltKopf(kopf string) string {
	var b strings.Builder
	for _, r := range norm(kopf) { … if unicode.Is(unicode.Mn, r) { continue } … }
	return field.SlugifyKey(b.String())
}
```

The doc comment is the load-bearing part and it must say all of this: the rule is
**strip combining marks, then `field.SlugifyKey`**, in that order and never the
other way round. `SlugifyKey` matches the single rune `'ü'` (U+00FC); a header
written on macOS, or exported by a tool that normalises to NFD, arrives as `u`
followed by U+0308, and `Grösse` would then silently fail to match its own field
— exactly the class of bug IMP-06 exists to prevent, and one that no test of the
*matching* would find unless the test itself is written in NFD. `unicode.Mn`
only; no `golang.org/x/text`, which stays the indirect dependency `go.mod`
already lists, on the ground `internal/template/dates.go:24` records for the same
call made once before.

Compose it in exactly one function so the documented rule and the code cannot
drift. Nothing else in this phase may call `field.SlugifyKey` on a header
directly, and the verify gate below measures that.

**`Automatisch(kopf []string, defs []field.Def) Zuordnung`** — the match, in this
order, and the order is the requirement:

1. Fold every header once with `FaltKopf`.
2. Walk **definitions in `field.List` order** — `ORDER BY position, id`, which is
   the order the operator sees on the field screen — and for each, walk the
   columns left to right. A field matches a header when the folded header equals
   `def.Key` **or** equals `FaltKopf(def.Label)`. The first column that matches
   takes it (IMP-06 ordering; IMP-01 adjacency).
3. A field is matched **at most once** automatically. A second column folding to
   the same key is left as `ZielNichts` **and carries a reason code** —
   `GrundSpalteSchonBelegt`, with the winning column's position as its argument —
   so the mapping screen says why in place rather than leaving an unexplained
   blank that reads as an oversight (IMP-06 adjacency).
4. A header folding to the empty string matches nothing and carries
   `GrundKopfLeer` (IMP-06 empty). Still mappable by hand.
5. The fixed targets are matched from their own folded names before the fields
   are walked, so a website that happens to define a field called „Titel" does not
   take the title column away from the page's own title. Accept for each a small
   closed set of spellings — `titel`; `adresse`, `slug`; `text`, `inhalt`;
   `zustand`, `status`; `schlagwoerter`, `schlagworte`, `tags` — as a table with
   the sentence saying the set is closed on purpose, because guessing more
   spellings is how a column silently lands on the wrong target.

```
type Zuordnung struct {

	Hinweise []Grund           // one per column: why it was left unmapped, or ""

}

	AusgangAktualisieren Ausgang = "aktualisieren"

type Grund string

type Urteil struct {
	Zeile   int      // the spreadsheet's row number, from csv.Zeilennummer
	Ausgang Ausgang
	Grund   Grund    // empty means it worked — importWordPressItem's discipline, kept
	Args    []string // what the template substitutes into the sentence
}
```
