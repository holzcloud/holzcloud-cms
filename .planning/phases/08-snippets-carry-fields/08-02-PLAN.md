snippet has its own form, so `Required` is meaningful there.

**`OfSnippets` — one query per website, not one per snippet.**

Write it beside `OfSnippet`, taking `OfBlockTypes` (:137-160) as the shape:
the same seventeen-column list, `WHERE website_id = $1 AND snippet_id IS NOT
NULL ORDER BY snippet_id, position, id`, accumulating into
`map[int64][]Def` keyed by `d.SnippetID`, and initialised to an empty map so a
caller never meets a nil one. Carry `OfBlockTypes`' cost comment across in the
same register: one query rather than one per snippet, because this runs on every
public render.

It diverges from `OfBlockTypes` in the one way `OfSnippet` diverges from
`OfBlockType`: a snippet may carry a group, so the rows of each snippet are
assembled into a tree the way `List` does (:63-84) before they go into the map —
top level in the slice, children hung on their group's `Sub`. A snippet's slice
must come out equal to what `OfSnippet` returns for the same snippet, element for
element and `Sub` for `Sub`, or the public render and the admin screen would
disagree about a website nobody has changed.

The `ORDER BY` is load-bearing beyond tidiness: `snippet_id` groups the rows so
one pass can build the map, and `position, id` is the same tiebreak `List` and
`OfSnippet` use, so the bulk path and the single path can never disagree about
order. Say so in the comment.

**`Move` — the fourth arm.**

Add `case current.SnippetID > 0: defs, err = s.OfSnippet(ctx, websiteID,
current.SnippetID)` to the switch at :380-390. Put it before the `BlockTypeID`
arm or after it, but keep the `default:` arm meaning the page's own fields — and
extend the comment above the switch to say what D-09 requires: each arm names its
carrier, and the `default:` arm is the page and not „whatever is left". A field
inside a snippet has nothing to swap places with outside it, exactly as one
inside a group or a block kind does not.

**`validate` — the arm that is a contrast, not a copy.**

Extend the existing `if d.ParentID > 0 || d.BlockTypeID > 0` clearing clause to
include `|| d.SnippetID > 0` so a snippet field carries no condition, and say why
in the comment beside the reason already there: a snippet's form is filled in as
a whole and a field that came and went within it would be a rule the person
filling it in cannot see.

Then add a **separate** `if d.SnippetID > 0` arm and write in its comment that it
is deliberately not the block-kind arm above it. Set `d.AppliesTo = ForBoth`,
because „gilt für Seiten / für Beiträge" has no meaning on a snippet — a snippet
is not a page and belongs to no content kind. Do **not** set `d.Required = false`,
do **not** call `blockKind(d.Kind)`, and do **not** narrow the kind palette at
all. The block-kind arm forces non-required because a page save must not fail on a
half-written block; a snippet has a form of its own where a required field can be
refused with a reason, so `Required` stays meaningful. And a block kind's palette
is narrowed (`BlockKinds()`, `field.go:152-176`) because a block freezes to HTML
when the page is saved, so a reference or a label field inside one would go stale
on the next rename — a snippet's values are resolved on the way out through
`field.Resolve`, exactly as a page's are, so that reason does not reach here and a
snippet offers `field.Kinds` in full, groups included. Write both sentences into
the comment; this is the one place in the phase where copying the analog would be
wrong and silent.

Two narrowings are deliberate and neither is a field kind. `AppliesTo` is forced,
as above. `Condition` is cleared, for the same reason it is cleared inside a group
and inside a block kind: `checkCondition` walks the page's own field list and the
CSS rule that hides a dependant is written for the page form, so a condition on a
snippet field would be stored and never honoured — worse than not offering it.
Say so in the comment rather than leaving it to be discovered.

Leave the block-kind arm exactly as it is.

**`MaxFields` — scoped to the carrier (D-05).**

The count at :232-238 is `SELECT COUNT(*) FROM page_field_defs WHERE website_id =
$1` with no namespace filter, so one budget of sixty is shared by three carriers
today and four after this phase. Replace it with a count scoped to the carrier
being written, naming all four namespaces explicitly per D-09 rather than
branching on „whatever is left":

- a snippet field counts `WHERE website_id = $1 AND snippet_id = $2` — which
  catches that snippet's group sub-fields too, since they carry `snippet_id`, and
  that is right: they are rows of the same form
- a block-kind field counts `WHERE website_id = $1 AND block_type_id = $2 AND
  snippet_id IS NULL`
- a group sub-field counts against the page's own budget, exactly as it does
  today — do not change that, or an existing website's limit moves under it
- a page field counts `WHERE website_id = $1 AND block_type_id IS NULL AND
  snippet_id IS NULL`

Build it as a `switch` in the same house style as `Move`'s, so the four arms are
readable side by side, and keep the sentinel `ErrTooMany` and the value 60.

Then correct the doc comment on `MaxFields` in `internal/field/field.go:205-215`.
It currently says the limit bounds „how many fields one website may define". That
sentence is what D-05 abolishes. The rationale below it — „a form with sixty extra
fields is a form nobody fills in correctly" — is already the argument for the
change: a form only ever renders one carrier's fields, so a per-carrier count is
what makes the stated reason true rather than aspirational. Rewrite the first
paragraph to say the limit bounds one carrier — the page's own fields with their
groups, one block kind, or one snippet — and leave the rationale sentence standing.
