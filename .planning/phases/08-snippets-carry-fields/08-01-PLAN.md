<objective>
The fourth namespace, from the schema to the theme, on one path.

`page_field_defs` already carries three namespaces — a page's own fields
(`parent_id IS NULL AND block_type_id IS NULL`), a group's sub-fields, and a
block kind's fields. This plan adds the fourth and follows one snippet field all
the way out: defined in the table, stored on the snippet, resolved on the way to
a theme, printed by a template. Nothing on a page or in a block editor changes.

Two things in this plan are one-way doors and the checkpoint at its head names
both. A released goose migration is never edited — a correction is `00048`. And
the moment a theme indexes `.Site.Bausteinfelder`, that name is a published
contract on the same terms `.Site.Snippets` already is.

The dangerous edit is `internal/field/store.go:59`. It reads
`WHERE website_id = $1 AND block_type_id IS NULL`. Without
`AND snippet_id IS NULL` every snippet field lands on **every** page's edit form
and in **every** theme's `.Page.Feldliste` — silently, visible only in a browser.
Phase 7 shipped two criticals of exactly this shape, both in code where every
counting gate passed. So the gate here is a behavioural test that reads back
through every query path, not a grep.

Purpose: SNIP-02 and SNIP-04 in full, and the spine SNIP-01, SNIP-03 and SNIP-05
are built on.
Output: migration `00047`, `Def.SnippetID`, `OfSnippet`, `snippets.fields`,
`.Site.Bausteinfelder` / `.Site.Bausteinliste`, and one public route wired
through to prove the whole path.
</objective>

on a snippet, resolved on the way out, printed by a template on **one** public
route. No other call sites, no bulk readers, no admin screen. The point is to
prove the whole path before ten layers are committed on top of it — and to write
the discriminator before any snippet field can exist to leak.

Take it in this order; each step is provable before the next.

**1. `Def.SnippetID` (`internal/field/field.go`).**

Add `SnippetID int64` directly beside `BlockTypeID`, with a German-flavoured doc
comment in the same shape: what 0 means, that this is a separate world sharing
one table, and a reference to migration `00047` rather than `00038`. A bare
`SnippetID int64` breaks the file's style.

**2. The discriminator, all six statements (`internal/field/store.go`).**

Append `COALESCE(snippet_id, 0)` as the **last** column of all five SELECT column
lists — `List`, `Sub`, `OfBlockType`, `OfBlockTypes`, `Get` — and append
`&d.SnippetID` as the last argument of `scanDef`'s `row.Scan`. The five lists are
transcripts of one another and `scanDef` reads them positionally; a list that
diverges loads a field silently with a zero value and nothing fails. Read the
German warning at `scanDef` before you touch any of them.

Then the WHERE clauses, one at a time:

- `List` (:59) gains `AND snippet_id IS NULL`. This is the edit the whole phase
  turns on. Without it every snippet field appears on every page's edit form and
  in every theme's `.Page.Feldliste`.
- `Sub` selects by `parent_id = $2` and its WHERE stays **exactly as it is**.
  A group may stand on a snippet as well as on a page, and its sub-fields then
  carry both `parent_id` and `snippet_id`; adding `AND snippet_id IS NULL` here
  would make every group under a snippet come back empty. `Sub`'s namespace is
  the group, and a group id is unique within the website, so the clause is
  already explicit in D-09's sense. Write that sentence into a comment above the
  query, because the pattern-match is the obvious wrong move.
- `OfBlockType` already narrows by `block_type_id = $2`; add `AND snippet_id IS
  NULL`, since a block kind's field never belongs to a snippet.
- `OfBlockTypes` narrows by `block_type_id IS NOT NULL`; add `AND snippet_id IS
  NULL`.
- `Get` selects by id and website and is a lookup rather than a listing — leave
  its WHERE alone, and only add the column to its list.

Now the `Create` INSERT (:246-258). Add `snippet_id` to the column list and a
`snippet` `any` variable beside the existing `parent` and `blockType`, NULL when
`d.SnippetID` is 0. Add `AND COALESCE(snippet_id, 0) = COALESCE($n, 0)` to the
position subquery's WHERE, so a snippet's fields are numbered within their own
level.

**That subquery is the sixth occurrence, and it is required.** The new column
appears in this file in two roles, not one: five times as the last entry of a

carries whatever a page's form carries. Say that in the doc comment, and name
