<objective>
The screen that defines a snippet's fields already exists. It just does not know
about snippets yet.

There is no per-block-kind field handler and no per-block-kind field template:
`?baustein=<id>` on `GET /admin/websites/{id}/felder` turns the one field screen
into its third mode. The snippet field **definition** screen is therefore a
fourth mode of that same screen — a query parameter, a struct member, one arm in
each of the places `{{if .BlockType}}` already stands, and no new route.

The one thing that is not a copy is the ownership check. The block-kind mode gets
it for free, because `blockTypes.Get` takes a website id and a block kind of
another site simply is not found. `snippets.Get` takes only an id, and the
existing snippet handler compares `sn.WebsiteID != websiteID` by hand at two
places. That comparison has to happen on both the GET that opens the mode and the
POST that creates the field, or an operator of one site reaches another's snippet
by typing its number. One helper, two call sites, and a test that types the wrong
number.

Purpose: SNIP-01's definition half, and SNIP-02's „not a third table" made
visible on a screen.
Output: the fourth mode, the link into it, and the tests that hold the
authorisation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `?textbaustein=<id>` in a URL → a website's field definitions | The id is typed by whoever holds the address bar; nothing else narrows which snippet it names. |
| the hidden `textbaustein` input in the field form → `field.Store.Create` | A POST body reaches the INSERT; the form is a courtesy, the body is not. |
| an operator of one website → another website's snippet | `snippets.Get` takes no website id, so the scoping is the handler's to do. |
