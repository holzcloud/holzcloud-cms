<objective>
Make the new evidence set for the changed `deploy/backup.sh`: one `nightly.sh con-chain` run from fresh containers on a clean tree, pinned to one evidence commit (ROB-03).

Purpose: the earlier evidence for the consistency, compatibility and full-disk requirements (`deploy/BACKUP-CONSISTENCY-RUN.md`, evidence commit e86d490) was made with a `backup.sh` that no longer ships; `docs/beta.md` binds every promise to the commit of its evidence and says that a change to a bound file means the set is made again. This plan makes it again. The set measures what the script now does under the same load as before (CON-01), whether a backup of the previous release still restores (CON-02), what the script does on a nearly full filesystem (CON-03, now with assertions that the failed night leaves nothing and does not block the next one) and, new, what it does with a status 24 (the four VANISH scenarios).

Output: the scratch evidence under `deploy/test/out/` (gitignored), the evidence commit sha, and a summary of the numbers in the SUMMARY of this plan. Nothing tracked is changed by the run itself.

Hard limits: as in plan 29-01. No file under `deploy/` or `.github/` is edited unless a defect is found (Task 2), and then in its own commit. The run takes about 35 minutes on this machine (the earlier set took 35 minutes 34 seconds); it is run in the background and awaited, not polled.
</objective>
