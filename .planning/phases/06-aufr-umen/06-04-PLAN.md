  <action>
Complete the tool. Keep the existing target table, pin constant, build function and
`-print-hashes` mode; add the three modes around them.

**Write mode** — no flag, the default. For each selected target, build into a
temporary file placed **beside the destination**, not in the system temp directory,
because a rename across filesystems fails; then rename it over the destination. A
failed build must therefore never leave a truncated `.wasm` in the tree. Print one
German, column-aligned line per target with the short name, the destination path
and the size in mebibytes, in the register of `tools/mkbundle/main.go:48–51`.

**`-check` mode** — build each selected target into a temporary directory, hash it,
hash the committed file at the destination, compare. On equality print one German
line per target confirming it is current. On a mismatch print the destination path,
both sha256 values, both sizes in bytes and both embedded Go versions, then the
German instruction that the file is rebuilt with `go run ./tools/wasm` — D-11 makes
that command the one named to a human who has to fix it. Both embedded versions
are printed because "the pin moved" and "the source changed" are the two causes of
a mismatch and the message must let a human tell them apart without a second
command. A missing committed file is a mismatch, not a crash: report it as absent
and keep going. Exit 1 after reporting **all** mismatches, never on the first one —
a tool that stops at the first of six turns one CI run into six.

**`-out <dir>` mode** — build the six into that directory, named after the
destination's basename, and touch nothing in the tree. This is the D-05 fallback
made real: if cross-host equality had failed, CI would build into
`$RUNNER_TEMP/wasm` and the tests would read from there. Implement it now even
though the gate passed, because it costs one branch and it is the documented answer
if a future Go release breaks reproducibility. `-out` combined with `-check` is a
usage error and exits 2.

Exactly one of write, `-check`, `-print-hashes` and `-out` may be selected;
any other combination exits 2 with a usage line naming the four modes. Positional
target short names continue to select a subset in every mode.

Expected state at the end of this task: `-check` **fails**, loudly, for all six
targets. The committed files were built by three different compilers and five of
six still stamp a module path that no longer exists. That failure is the evidence
the tool works. The rebuild that turns it green is plan 06-05.

Run `gofmt -w tools/wasm/main.go` before committing.

Four of the five plugin directories carry an archive holding a byte-identical copy
of the module beside it. Rebuilding the modules without repacking would recreate,
one layer up, exactly the defect MAINT-03 exists to close — self-inflicted, which
is why D-23 puts it in scope rather than deferring it.

Extend `tools/wasm` to pack the four archives: `plugins/bestellung/bestellung.zip`,
`plugins/jahreszahl/jahreszahl.zip`,
`plugins/nicht-gefunden/nicht-gefunden.zip` and `plugins/suche/suche.zip`.
`plugins/kontaktformular` has no archive and gets none — it carries a `migrations/`
directory that a flat archive would flatten wrongly. Record that exception in a
comment beside the archive table so it does not look like an oversight.

Each archive holds exactly two flat entries in this order: the plugin manifest,
then the module. No directory prefix — this matches what the four committed
archives contain today and what the README's archive command produces.

Determinism is the point, so `archive/zip`'s defaults are not enough. Set an
explicit fixed `Modified` timestamp on every `zip.FileHeader`; left unset,
`archive/zip` stamps the current time and two runs produce different bytes. Pick
one constant instant, declare it as a package-level value with a comment saying why
it is fixed, and use it for both entries in all four archives. Use one compression
method consistently across every entry. Build the whole archive in a
`bytes.Buffer` and write it with a single `os.WriteFile`, the shape
`tools/mkbundle`'s packer already uses and for the reason its comment gives: an
archive interrupted half-way still looks like a file.

Wire the archives into all four modes. Write mode packs them after the modules it
just built. `-check` hashes each built archive against the committed one and
reports a mismatch in the same shape as a module mismatch, so the exit status
covers all ten artifacts. `-print-hashes` prints them. `-out` writes them into the
target directory. A target selected positionally carries its archive with it; a
target with no archive simply has none.

Prove determinism inside the task: pack twice into two temporary directories and
compare the bytes. If they differ, something is still stamping — find it before
moving on, because the whole comparison rests on this.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| documented build command → contributor's shell | a README that omits a flag produces artifacts CI rejects and the contributor cannot diagnose |
| built artifact → committed artifact | `-check` is the only thing that asserts the two are the same |
| `archive/zip` default header → committed archive | an unset `Modified` field silently stamps wall-clock time and destroys determinism |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-12 | Spoofing | committed `.zip` archives holding a stale copy of a rebuilt module | high | mitigate | D-23: `tools/wasm` packs all four deterministically and `-check` compares them, so the rebuild cannot desynchronise them |
