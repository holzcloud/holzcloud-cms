<assumption_delta_decision>
**Family: pluralization.** A value slot that was singular acquires a plural case.
The deterministic assumption-delta scan fired on this phase; 07-CONTEXT.md already
answers it in two places and two different ways. Both are recorded here and are
**not** to be re-opened during execution.

**Primary noun:** the field *value slot*. It is **plural (`[]string`) at the render
contract** and **a joined string in storage**. Exactly one exported pair
(`SplitValues` / `JoinValues`) converts between the two spellings.

**Decision — two moves, deliberately different:**

- **`promote`, at the render contract (D-02).** `Entry` gains `Values []string`
  and `Resolve` / `List` / `Filled` gain a `case []string`. The general
  representation becomes primary where a theme reads it.
- **`add-alongside`, at the kind level (D-05).** `mehrfachauswahl` is a **new kind
  beside** `auswahl`, not `auswahl` acquiring `max_werte > 1`. The reason is
  measured, not preferential: `internal/field/render.go`'s `Resolve` has **no
  `case KindChoice`**, so a Choice falls through to the default branch and reaches
  a theme as a plain string. Promoting `auswahl` to multi-valued would silently
  retype what every existing theme on every existing site already reads, with no
  error anywhere.

**Accepted debt:** the two kinds stay separate for this milestone, so a website
that wants "one or many of the same option list" configures two fields.

**What would force a later promote:** a requirement to merge `auswahl` and
`mehrfachauswahl` behind one kind with a `max_werte` cap. That is not a refactor —
it needs a data migration for every site that already stores values under the
`mehrfachauswahl` key **and** a theme-contract change, because a theme that today
reads a Choice as a string would start receiving a slice. 07-CONTEXT.md
`<deferred>` already records this; nothing in this phase may be built in a way
that assumes the merge is coming.

**Companion invariant:** Task 3's two tests are that invariant. Every multi-valued
field round-trips through the one exported pair — page form, storage, `Resolve`,
bundle export, bundle import — so Phase 9's CSV importer cannot reintroduce a
second spelling without turning them red. The CSV pipe separator
(`REQUIREMENTS.md:292`) is a boundary conversion inside that importer, not a
second mode of these functions.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → admin page form | An authenticated editor's POST body. Field names and values are attacker-influenced text; `feld_<key>[]` is a repeated key of unbounded arity. |
| stored value → theme render | A joined string leaves storage and reaches a template as `[]string`. |
| bundle file → import | A bundle is a file an operator supplies; its field values are text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Denial of Service | `fieldsFromRequest`, `internal/admin/page_form.go` | medium | mitigate | A repeated `feld_<key>[]` key is bounded twice: Go's `ParseForm` caps the urlencoded body at 10 MB, and `CheckAll` rejects a joined value over `MaxValueBytes` rather than storing it. Plan 07-04 adds the reporting half; this plan must not add a truncating path that would hide the overflow. |
| T-07-02 | Tampering | `fieldsFromRequest` key parsing | medium | mitigate | The `[]` marker is tested with `strings.CutSuffix` after `CutPrefix("feld_")`, and a key that is empty after trimming is skipped. A field key is slug-like and cannot contain a bracket, so a crafted name cannot address a different field. Values are still filtered by `field.Clean` against the loaded definitions before storage. |
| T-07-03 | Tampering | `Check` for `KindMulti` | medium | mitigate | Every submitted value is compared against `d.Choices`; a value not on the list is reported and the save is refused. The option list is a closed vocabulary, so an arbitrary string cannot enter storage through a checkbox group. |
| T-07-04 | Information Disclosure | the checkbox group in `field_input.html` | low | accept | Values are echoed back into the form through `html/template`, which escapes them contextually. No `template.HTML` cast is made anywhere on this path. |
| T-07-SC | Tampering | package-manager installs | low | accept | No `go get`, `npm`, `pip` or `cargo` install task exists in this phase — every symbol is Go standard library or already in `go.mod`. The package-legitimacy gate does not fire, and no legitimacy checkpoint is needed. |
</threat_model>
