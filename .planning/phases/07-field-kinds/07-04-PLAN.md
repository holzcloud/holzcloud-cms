<objective>
Close the two guards a genuinely multi-valued field needs, and carry the marker
into a group's rows.

Plan 07-01 made three values arrive as three values. This plan makes an
over-long or over-numerous set say so instead of quietly becoming something
smaller. `MaxValueBytes` is now shared across all of one field's values, and the
one place that used to shorten a too-long value did it silently — for a
multi-valued field that would cut a value in half, and neither the author nor the
theme would ever learn that it happened.

The second half is the marker inside a group. `fieldsFromRequest` has a twin line
for a group's rows, and a `mehrfachauswahl` inside a group would hit it and keep
only the first ticked value. The fix is the same one D-03 already chose: the
marker is minted in one place, never spelled out at a call site.

Purpose: make the encoding honest under pressure, and complete on both of its
two paths.
Output: `max_werte` enforced, the shared budget reported, and group rows carrying
the marker.
</objective>

**The cap (D-05).** In `Check`, extend the `KindMulti` case added in plan 07-01:
after checking that every value is on the option list, count the values with
`SplitValues` and, when `d.MaxValues` is greater than zero and the count exceeds
it, return a German reason naming the field's label and the maximum, in the
register of the existing reasons — written for the person filling the form in,
not for a log. A maximum of zero means no cap; that is what every field already
in a database carries and nothing about them may change.

The cap has to live here rather than in markup: a checkbox count cannot be capped
in HTML without JavaScript, and this program carries none beyond htmx.

**The shared byte budget (D-13).** `MaxValueBytes` is now the budget for all of a
field's values together, joined, including the newlines between them. Two
changes:

1. Add a length guard near the top of `Check`, after the empty-value guard and
   before the per-kind switch, so it applies to every kind: when the trimmed
   value's byte length exceeds `MaxValueBytes`, return a German reason naming the
   field's label and the limit. Compare with `len` on the Go string — bytes, not
   runes: the limit exists to bound what goes into the database, and the database
   counts bytes.
2. The helper just above `Check` that both trims whitespace and shortens an
   over-long value must stop shortening. Leave the whitespace trimming, which
   every caller relies on, and remove the slicing. Its doc comment gains one
   sentence saying that an over-long value is now reported by `Check` before it
   can reach here, so shortening would only ever hide the report. For a
   multi-valued field the old behaviour would have cut a value in half and stored
   the fragment as if the author had typed it, which is precisely the failure
   this phase exists to make impossible.

Do not add a second, quieter shortening anywhere else to compensate. If a write
path is found that does not run `CheckAll`, name it in the SUMMARY rather than
patching around it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → page form | An authenticated editor's POST body. `feld_<key>[]` and `gruppe.<key>.<n>.<sub>[]` are repeated keys of unbounded arity. |
| checked values → stored JSON | The joined string enters `pages.fields` as one value. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-15 | Denial of Service | the joined value of a repeated form key | high | mitigate | This task is the mitigation. `Check` refuses a joined value over `MaxValueBytes` and `CheckAll` refuses a count over `Def.MaxValues`, both before anything is written. Go's `ParseForm` already caps the urlencoded body, so the two limits together bound both the request and the row. Boundary tests assert the limit itself passes and one over it is refused. |
| T-07-16 | Tampering | `parseRowName` | high | mitigate | Every existing guard survives the widening: the `gruppe.` prefix, the exactly-three-parts check, and the index bounds check against `MaxRows`. The marker is stripped with `strings.CutSuffix` after those guards, so a crafted name cannot address a row outside the bound or a fourth namespace. |
| T-07-17 | Tampering | values not on the option list | medium | mitigate | `Check`'s `KindMulti` case compares every submitted value against `d.Choices`; the option list is a closed vocabulary, so a hand-crafted POST cannot put an arbitrary string into storage through a checkbox group. |
| T-07-18 | Repudiation | the removed shortening | low | mitigate | Removing the silent shortening is what makes the failure legible: an author who typed too much now sees a reason instead of discovering later that the stored text ends mid-word. There is no remaining path that writes a shortened value without saying so. |
| T-07-SC | Tampering | package-manager installs | low | accept | No `go get`, `npm`, `pip` or `cargo` install task exists in this phase — every symbol is Go standard library or already in `go.mod`. The package-legitimacy gate does not fire, and no legitimacy checkpoint is needed. |
</threat_model>
