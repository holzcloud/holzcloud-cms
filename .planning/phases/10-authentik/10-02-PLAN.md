<objective>
The security core, built and proved before anything is allowed to rest on it.

This plan introduces **the first place in this codebase that trusts a header's
claim about identity**. Every other header this program reads is one of two
things: a secret the server verifies for itself (`/ai`'s bearer token), or a
value whose only guarantee is who the peer is (`X-Forwarded-For`,
`X-Request-ID`). A forward-auth header is neither. It is a claim, and the only
thing standing behind it is the socket it arrived on.

So the order in `ROADMAP.md`'s planning notes is not a preference. Layer 1 is the
peer address, checked **before any header is read**. Layer 2 is stripping every
inbound copy of every identity header **in this program**, not only in Caddy,
because CVE-2026-30851 means `forward_auth … { copy_headers X-Foo }` generates a
conditional set with **no delete** — so on an operator's Caddy between 2.10.0
and 2.11.1, a client's own `X-authentik-email` reaches the backend verbatim
whenever the outpost answers 200 without emitting that header. Layer 2 is what
makes that a misconfiguration on someone else's server rather than a bypass
here. Layer 3 is the shared secret. Layer 4 — a signed assertion — is
deliberately not built, and the reason is written into the source so it is not
relitigated.

**Nothing in this plan signs anybody in.** After it lands, a correct request from
the proxy carries an identity in its context and every handler ignores it. That
is the shape the build order asks for: the gate exists before there is anything
behind it worth reaching.

**The one gate this plan must not get wrong.** A grep for the word `strip` proves
nothing about stripping. The gate here reads the header map of a request that has
been through the middleware and asserts that no key in it normalises to the
`x-authentik-` prefix — measured from the far side, against a request carrying
every spelling anybody has published, including the underscore one.

Purpose: SSO-02, SSO-03 and SSO-04, and criterion 2's four clauses.
Output: one middleware, one context accessor, and the test file that is most of
this plan's weight.
</objective>

`strings` and `context`, and **nothing from this repository except what is
already in package `web`**. It must not import `internal/config`: the options

**The package-level doc block, three paragraphs, in `logging.go:26-30`'s
voice.** First: what forward authentication is and what arrives. Second — and
this is the paragraph the phase exists to write — the distinction this codebase
already draws and now extends. `/ai`'s `Authorization: Bearer` is a **secret the
server verifies independently**; `X-Forwarded-For` is a **value whose only
guarantee is who the peer is**; a forward-auth header is a **claim about
identity**, and nothing in this program trusted such a claim before this file.
Third: the four layers, named, in order, with one sentence each on what failure
of the layer above it covers.

**`ProxySecretHeader`**, an exported constant, `"X-Holzcloud-Proxy-Secret"`. Its
own name and not authentik's, because it is this installation's secret and not
the identity provider's, and because a header the proxy adds must be
distinguishable from one it copies.

**`Identity`** — `Username`, `Email`, `Name`, `Groups []string`. The comment says
which header each comes from and carries D-02: the identity is pinned to
`X-authentik-username` and **not** to `-uid`, because `-uid` is the OIDC `sub`
and its shape depends on the provider's Subject mode, whose default is a hashed
identifier. `-uid` is read into nothing; it is stripped like the rest.

**`ForwardAuthOptions`** — `Enabled bool`, `Secret string`. Two fields, so a test
constructs one in a line.

**`ForwardAuth(resolver *ClientIPResolver, opts ForwardAuthOptions) func(http.Handler) http.Handler`.**
The body is short and its order is the requirement. Write it so that the source
order *is* the proof, and say so in a comment:

1. **`var ident *Identity`**, then a single guarded block whose condition is
   `opts.Enabled && opts.Secret != "" && resolver != nil && resolver.IsTrustedPeer(r) && secretMatches(r, opts.Secret)`.
   Go's `&&` short-circuits left to right, so on an untrusted peer
   `secretMatches` is never called and **no header is read at all**. That is
   criterion 2's "the peer is checked before any header is read", literally, and
   the comment says that the ordering is the mechanism rather than a style
   choice. Inside the block, read the seven headers with `r.Header.Get` — never
   map indexing, because `Get` canonicalises and indexing does not — and build
   the identity. An identity with an empty `Username` is not an identity: leave
   `ident` nil, because the one field everything downstream keys on must be
   present.
2. **`stripIdentityHeaders(r)` — unconditionally, on every path, after the
   capture and before `next`.** This is layer 2 and its whole value is that it
   has no condition.
3. If `ident != nil`, put it in the context. Otherwise pass `r` on untouched.
4. `next.ServeHTTP`, exactly once, on every path.

**`stripIdentityHeaders(r *http.Request)`.** Do not delete a list. Iterate
`r.Header`'s own keys, normalise each with
`strings.ToLower(strings.ReplaceAll(k, "_", "-"))`, and delete the key when the
normalised form has the prefix `x-authentik-` or equals the normalised
`ProxySecretHeader`. Collect the keys first and delete afterwards, because
deleting from a map while ranging over it is a thing to get right rather than to
find out about. The comment carries the reason the scan is a scan: Go
canonicalises `-` but not `_`, so `X-authentik-email` and `X_authentik_email` are
two distinct map keys (CVE-2026-52845 / GHSA-f59h-q822-g45g is the companion
advisory that made this a published problem rather than a theoretical one) — and
a fixed list of hyphenated names is a list somebody has to keep up to date with a
program on another machine. **The scan is the guarantee; the header names in the
doc comment are documentation.**

**`secretMatches(r *http.Request, want string) bool`** — one line of
`subtle.ConstantTimeCompare([]byte(r.Header.Get(ProxySecretHeader)), []byte(want)) == 1`.
The comment says what constant time does and does not buy: it hides the position
of the first differing byte and not the length, and the length of a secret an
operator chose is not the secret.

**`splitGroups(raw string) []string`** — `strings.Split` on `"|"` (U+007C,
verified from authentik's own `getHeaders` in
`internal/outpost/proxyv2/application/mode_common.go` at tags
`version/2026.8.1` and `version-2025.8`), each element trimmed, empty elements
dropped. The comment states the trap in one sentence: an empty header split on a
pipe yields a slice of one empty string, and a membership test against that
slice would make "" a group.

**`(Identity) HasGroup(name string) bool`** — a whole-element comparison over the
slice. The comment names the naive form it replaces: `strings.Contains` on the
raw header matches `not-holzcloud-admins` when asked about `holzcloud-admins`.
The function exists so plan 10-05 cannot get this wrong in a hurry.

**`IdentityFromContext(ctx context.Context) (*Identity, bool)`** over an
unexported key type, in the shape `RequestIDFromContext` (`logging.go:21`)
already uses.

**Layer 4, written down and not built.** A block comment near the end of the
file, headed so a reader looking for it finds it: a signed assertion is
deliberately **not** implemented for v1.6. Verifying authentik's proxy JWT means
either fetching JWKS at runtime — the one rule this project does not break — or
pinning a key; and without a signing key authentik signs proxy tokens
*symmetrically with the client secret*, so "verify" is two modes plus holding
that secret. The signature protects nothing the transport does not: an attacker
who can set headers on that socket can talk to the CMS directly. And parsing a
JWT without verifying it is **strictly worse than not having it**, because it
looks like a defence. `X-authentik-jwt` is therefore stripped like every other
header and read by nothing.

Write `forwardauth_test.go` with one named English subtest per line of the
behaviour list. The strip assertion is written from the far side: a handler
installed behind the middleware records `r.Header`, and the assertion walks that
map and fails on any key whose normalised form carries the prefix. Table-drive
the twelve spellings so adding a thirteenth is one line.

**First: criterion 2, run for real, against a running binary.** The in-process
test in task 2 proves the middleware. It does not prove the binary, the router
order, or the listener — and criterion 2 is stated as a command against a
server, so it is run as one.

The obstacle is honest and must be named in the script's own comment: **there is
no second machine here, and the obvious substitute silently passes for the wrong
reason.** If the server binds loopback (which is now the default) and the command
is run from another host, the answer is `Connection refused`. That is a pass in
the sense that no dashboard was returned, and it proves **nothing at all** about
layers 1 to 3 — it proves the listener. This is precisely the failure shape
`10-CONTEXT.md` names: a gate that proves a proxy is not a gate.

So the gate is constructed to be reachable and still untrusted:

1. Start the freshly built binary with `HOLZCLOUD_LISTEN=0.0.0.0`,
   `HOLZCLOUD_SSO_ENABLED=true`, `HOLZCLOUD_SSO_SECRET=…` and

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the network → the listening socket | Anything can connect and send any header. `req.RemoteAddr` is the only thing about the connection a client cannot choose. |
| the reverse proxy → this program | The proxy's assertions are believed here and nowhere else in the codebase. Believing them rests on the peer address, the shared secret, and nothing else. |
| an operator's Caddy → this program | CVE-2026-30851 means the operator's proxy may forward the client's own identity header verbatim. This boundary is assumed broken and layer 2 covers it. |
| `internal/web` → every handler in the binary | After this middleware no handler can read an identity header. That is enforced by deletion, not by convention. |

Layer 3: the shared secret, constant-time. Proved in-process over IPv4 and IPv6 and live against a running binary from a non-loopback address. |
