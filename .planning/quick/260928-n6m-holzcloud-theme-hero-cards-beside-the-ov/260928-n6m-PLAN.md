<objective>
In the shipped public theme `holzcloud`, stop the phone from pushing the Karten out of the first screen.

v0.0.6 (quick task 260928-l3g) draws a second image after the hero window as a phone. The phone sits over the lower right of the window. On holzcloud.ch at 1440x900 it hangs about 380px below the window, and the strengths cards (`… + .hc-bild + .hc-bild + .hc-karten`) start below it, outside the first screen.

**What the user decided:**
- **Wide screens.** The cards move up right under the hero window. They sit to the LEFT of the phone's overhanging part, with free space on the right as wide as the phone plus its inset and a gap.
- **The phone** keeps its size and its position over the window.
- **The next block** after the cards must start below the phone's bottom.
- **Narrow screens** (below 60em) keep today's stacking.
- **Pages without a second image** stay exactly as they are.

**How: one grid row for phone and cards, from 60em up.** `.page-content` is a grid. Every block is a direct grid item, and the phone and the cards both span `text-start / breit-ende`.
- **Why explicit rows.** Automatic grid placement never puts two items into overlapping cells, and in the default sparse mode it only moves forward. So the cards can share the phone's row only if both get an explicit row. `dense` would pull later blocks into earlier holes, and `order` would need an extra column track plus a reordered rest of the page, so neither is used.
- **The row numbers.** The Vorspann is row 1, the window row 2, and phone plus cards row 3. These numbers are only right when the Vorspann is the first block. So the new rules require `.hc-eigen--vorspann:first-child`. A page that puts a block before the Vorspann falls back to today's stacking, which is safe.
- **Live data checked while planning.** In holzcloud-sites/holzcloud-ch/holzcloud.json, every holzkube-manager, holzcloud-cms and hauscloud page in all locales starts with `vorspann, bild, bild, karten, stand`.
- **Why this is robust.** A shared row makes its height the larger of the phone's overhang (its margin box after the negative top margin) and the cards' height. The next block therefore starts below whichever ends lower. That holds without knowing the screenshot's aspect ratio, which CSS cannot know.
- **Keeping the cards clear of the phone.** The cards get `margin-inline-end` equal to phone width + inset + a gap. Both values come from the same custom properties the phone uses. Their `%` values resolve at the point of use against the same grid area, so the reservation always matches the phone.

Purpose: on the program pages of holzcloud.ch, the first screen shows window, phone and strengths together.
Output: `cmd/holzcloud/templates/public/holzcloud/style.css` (CMS layer only) and `CHANGELOG.md` (0.0.7). Harness files stay in the scratch directory.
