# Quick Task 260903-94n: Theme Holzcloud Summary

The holzcloud.ch design ships as the eighth built-in public theme (slug `holzcloud`, name `Holzcloud`) — twelve views over a byte-identical copy of the holzcloud-design system, with Manrope and JetBrains Mono vendored into the theme and served from its own origin.

## What Was Built

**The theme directory** — `cmd/holzcloud/templates/public/holzcloud/`, 15 files plus `fonts/`:

- `style.css` (1712 lines) in four parts: a provenance header, four `@font-face` blocks, the four design-system files verbatim between sentinels, and an unlayered CMS layer replacing holzcloud.ch's `site.css`.
- `layout.html` — the full `<head>` from schlicht minus every font-host reference, `bausteine.css` before `/t/style.css` before `.Site.Design`. The `<body>` opens with the cube texture, then the skip link, then a `.hc-bar` that is a direct sibling of the texture.
- Twelve views: `page home list search gate 404 maintenance shop product cart checkout order`.
- `favicon.svg` — the cube mark with a fixed brass on the dark ground, since a favicon inherits nothing.

**The registration** — one entry in `BuiltinTemplates`, one entry in `TestShippedThemesRenderEveryView`.

**The provenance** — a `## Schriften` section in `VENDOR.md` with source URLs, sizes, SHA-256 values, licence and a runnable update recipe; one amended clause in `CLAUDE.md`.

## How the Cascade Works

Three steps, no `!important` anywhere:

1. `@layer hc.tokens|hc.base|hc.components|hc.motif` — the design system.
2. The unlayered CMS layer — beats all four, because unlayered CSS beats every layer regardless of file order.
3. `.Site.Design` in a `<style>` after the stylesheet — unlayered and later, so it beats the CMS layer.

The operator's six tokens land in step 3. `--hc-ink` and `--hc-measure` take effect by name alone; the other four are bridged one-way in step 2 (`--hc-brass ← --hc-brand`, `--hc-ground ← --hc-paper`, `--hc-font-sans ← --hc-font`, `--hc-r ← --hc-radius`), each with the tokens.css value as fallback. The direction is always regler → system, never back — the reverse would be a custom-property cycle and both values would drop out.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The header prose broke its own `cmp` gate**

- **Found during:** Task 1, first assembly of `style.css`
- **Issue:** The provenance comment explained the sentinels by quoting them: `Zwischen den beiden Marken „verbatim begin" und „verbatim end"`. The gate is `awk '/verbatim begin/{f=1;next} /verbatim end/{f=0} f'`. That one line matched the opening pattern 46 lines too early, and `next` skipped the closing match on the same line — so the extracted region would have begun inside the header and the byte comparison would have failed for a reason that had nothing to do with the CSS.
- **Fix:** Rewrote the sentence to say "Zwischen den beiden Marken darunter" without quoting either literal. The file now contains each sentinel string exactly once.
- **Files modified:** `cmd/holzcloud/templates/public/holzcloud/style.css`
- **Commit:** 6f13522

### Additions Beyond the Letter of the Plan

**2. [Rule 2 - Missing critical] Four more generic names bridged to bausteine.css**

The plan named six (`--ink --paper --brand --line --space-3 --radius`). `bausteine.css` also reads `--space-4`, `--step--1`, `--step-1` and `--step-2` with hard-coded rem fallbacks; without them four block rules would have sat on 2rem/1.25rem/1.5rem/0.875rem instead of the type scale. All ten are bridged. `.hc-video` reads `--hc-radius` and `--hc-space` directly — those are the operator's own names, so bridging them at `:root` would have been the cycle described above; the two rules are targeted instead.

**3. [Rule 2 - Missing critical] Derived tokens restated so the brand actually carries**

The plan asked for `--hc-ink-2`/`--hc-ink-3` as `color-mix` over `var(--hc-ink)`. The same argument applies to the brass alphas (`--hc-brass-soft`, `--hc-brass-wash`, `--hc-pane-lift`) and — more consequentially — to the ground: `--hc-ground-2` is the light end of the page gradient, and left as a literal an operator who set `--hc-paper` would have seen their colour at one end of the gradient and holzcloud's dark brown at the other. Each restatement reproduces its tokens.css value with the default inputs (`--hc-ground-2` = `color-mix(in srgb, var(--hc-ground) 96%, var(--hc-brass) 4%)` → `#140D08`).

`--hc-brass-pulse-out` was deliberately **not** restated: it is a zero-alpha brass rather than `transparent` so the pulse animation does not travel through grey, and `color-mix(…, 0%, transparent)` would have produced exactly the `transparent` tokens.css avoids. A comment records why.

**4. [Rule 2 - Missing critical] `aria-invalid` on checkout fields**

`components.css` styles `.hc-input[aria-invalid="true"]` and its comment says the red border is driven by the attribute assistive technology reads, "so the red border cannot disagree with what gets announced". Schlicht's checkout prints the error text but sets no attribute. Every field with an entry in `.Checkout.Errors` now carries both.

## Notes on Two Plan Decisions

**The skip link is not the first element in `<body>`** (D-05). `motif.css` lifts content over the texture with `.hc-cubes ~ *` and restores the bar's `sticky` with `.hc-cubes ~ .hc-bar`; both are sibling rules, so the texture has to come first and the bar has to be a direct sibling of it. What TEMPLATE-SPEC §10 protects is that the skip link is the first *focusable* element, and it is — `.hc-cubes` is an `aria-hidden` decorative `<div>` with no tab stop. Placed before the texture it would have painted underneath it when focused.

**The class attribute is exactly `class="skip-link"`.** The suite greps for that string verbatim, so `class="skip-link hc-skip"` would not have matched. The CMS layer restates the `.hc-skip` rules under the shipped-theme name.
