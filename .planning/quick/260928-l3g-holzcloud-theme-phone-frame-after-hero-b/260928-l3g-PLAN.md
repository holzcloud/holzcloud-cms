<objective>
Two changes to the shipped public theme `holzcloud`, made in its stylesheet only. The theme is used by holzcloud.ch, and screenshots from the user's phone showed both problems.

1. **Phone after the hero.** When a second `.hc-bild` follows the hero window directly (Vorspann, Bild, Bild, Karten), draw that second image as a phone: CSS-only device frame, overlapping the lower right of the window, cards unchanged below it. Without a second image nothing changes.
2. **Bildtext heading above the image.** Every bildtext block whose text starts with a heading shows that heading across the full width above the image. Below it, image and text sit side by side on wide screens and stack on narrow screens.

**Approach decision for (2), and why it is CSS-only.** A markup change was evaluated and rejected, for four reasons:
- **Save-time rendering.** `block.Render` runs when an editor presses Save and writes into `pages.content_html` (see the doc comment in `internal/block/words.go`). A change in `render.go` would therefore reach no existing page until every page is saved or imported again.
- **Shared contract.** The block HTML is a contract shared by all 8 shipped themes and by every uploaded theme. Moving the heading out of `.hc-bildtext__text` would silently change the look of themes this repository cannot see.
- **Tables do not work.** A pure-CSS table trick (heading as `table-caption`, text grouped in an anonymous cell) does not work either: the heading sits between the image and the paragraphs in the DOM, so the caption breaks the anonymous-row run and the paragraphs land in a second row.
- **Grid does.** The chosen technique uses grid. `.hc-bildtext__text` gets `display: contents`, so the heading and every paragraph become grid items of `.hc-bildtext`. The heading spans row 1. On wide screens the image spans the rows beside the text, and a trailing `1fr` row soaks up the image's extra height, so paragraphs never spread apart (CSS Grid 1 flexible-track sizing).
- **Guarded.** A `:has()` guard applies all of this only when there is an image and the text starts with h2/h3. Everything else, and browsers without `:has()`, keep today's layout.
- **What stays untouched.** `internal/block/render.go`, `internal/tmplspec/TEMPLATE-SPEC.md`, `cmd/holzcloud/assets/bausteine.css`, the other seven themes and all tests stay as they are.
- **One trade-off.** DOM and reading order stay image, heading, text; only the visual order changes. This matches the reasoning bausteine.css gives for `--rechts`.

Purpose: holzcloud.ch program pages get a device-pair hero, and the feature rows read heading first on every screen size.
Output: `cmd/holzcloud/templates/public/holzcloud/style.css` (CMS layer only), `CHANGELOG.md` (0.0.6 paragraphs). All harness files stay in the scratch directory.
</objective>
