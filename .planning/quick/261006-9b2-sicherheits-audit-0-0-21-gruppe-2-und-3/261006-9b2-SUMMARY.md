## Choices to report
- **requireFresh and uploads:** RequireFreshPassword redirects (303) to the confirm page and does not replay the body. The upload forms are plain forms, not htmx, so the redirect works. The user confirms, returns via Referer, and re-selects the file. I wrapped the POST routes as planned and did not gate the GET pages.
- **Consequence:** SSO-provisioned accounts that have no password cannot pass requireFresh, so the new routes are blocked for them as well. The elevate.go doc comment and the CHANGELOG say so.
- **main_test.go:** the classification tables do not record freshness. I added `TestSensitiveRoutesAskForThePasswordAgain`. It drives the two 2fa routes for real. The other five sit behind the 2FA setup gate, which a fixture admin never passes, so for them the test reads main.go and requires `requireFresh(` on each registration.

## Deviations from plan
- **[Rule 2]** A strict "only own prefix" rule would have broken the shipped contact-form migration (it reads form_messages/pages and writes plugin_store). I therefore added the plugin_store-with-own-id and read-allow-list exceptions.
- Triggers and views are refused outright instead of being checked for prefixed references, because trigger bodies cannot be validated by a text check.

## Known limits (accepted)
- The prefix `plugin_a_` also covers the tables of a plugin whose id is `a-b` (`plugin_a_b_`).
- The plugin_store check is a heuristic: the own-id literal must appear in the statement.
- `POST /admin/users/new` (creating an admin) is not in the plan's list and is not wrapped. Worth a follow-up.
