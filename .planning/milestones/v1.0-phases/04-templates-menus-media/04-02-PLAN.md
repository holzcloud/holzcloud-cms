- `HandleTemplateUpload(w, r) error` — GET shows upload form, POST processes:
  - `r.Body = http.MaxBytesReader(w, r.Body, cfg.MaxTemplateSize)` (D-03)
  - Save uploaded file to temp location
  - Call `tmplmgr.ExtractTemplate(...)` with temp dir then rename to `data/templates/{slug}/`
  - Call `tmplmgr.ValidateTemplateStructure(...)` (D-04)
  - Create DB record via store.Create()
  - Flash success, redirect to /admin/templates
  - On error: flash error, redirect back
- `HandleTemplateActivate(w, r) error` — POST /admin/templates/{id}/activate. Read websiteID from form value. Call store.ActivateForWebsite(). Call loader.InvalidateTemplateCache(websiteID). Flash success. HX-Redirect or 303.
- `HandleTemplateDeactivate(w, r) error` — POST /admin/templates/{id}/deactivate. Similar.
- `HandleTemplateDelete(w, r) error` — POST /admin/templates/{id}/delete. Check IsActiveAnywhere (D-08); if active, flash error. Otherwise store.Delete(). Redirect.

**templates/admin/template_list.html** — Follow existing admin template patterns. Show table of templates (name, slug, status per website, created_at). Upload button links to upload form. Each template row has activate/deactivate toggle per website (dropdown or section) and delete button with confirmation.

**templates/admin/template_upload.html** — Simple form with file input for .zip, name field. `enctype="multipart/form-data"`. CSRF token. Submit button with `hx-disabled-elt="this"`.

Both templates use `{{template "base" .}}` / `{{define "content"}}` pattern. Maintain Linear/Ghost aesthetic from existing admin CSS.
