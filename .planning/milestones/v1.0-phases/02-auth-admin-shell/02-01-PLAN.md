<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Server | Untrusted credentials (email/password) and session tokens |
| Session cookie | Client-controlled token used to look up server-side session |
| CSRF token | Prevents cross-origin state-changing requests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | password.go | mitigate | Argon2id with constant-time comparison via subtle.ConstantTimeCompare; PHC format stores params per-hash |
| T-02-02 | Tampering | sessionstore.go | mitigate | SCS signs session tokens; server-side storage means client cannot modify session data |
| T-02-03 | Repudiation | middleware.go | accept | No audit log in v1; low risk for single-admin Pi deployment |
| T-02-04 | Information Disclosure | password.go | mitigate | Same error message for wrong email and wrong password ("Invalid email or password") |
| T-02-05 | Denial of Service | password.go | accept | No rate limiting in v1 per user decision; Argon2id 64MB cost provides natural throttle |
| T-02-06 | Elevation of Privilege | middleware.go | mitigate | RequireAdmin checks role from session; role set only on login from DB value |
| T-02-07 | Spoofing | session.go | mitigate | Session ID rotated on login via RenewToken (prevents fixation); HttpOnly + SameSite=Lax cookies |
| T-02-08 | Tampering | csrf.go | mitigate | gorilla/csrf validates X-CSRF-Token header; key persisted in data/csrf.key with 0600 perms |
</threat_model>
