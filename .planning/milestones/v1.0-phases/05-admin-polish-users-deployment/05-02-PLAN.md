Per D-15: if `sessionUserID == targetID`, require `current_password` field and verify with `auth.VerifyPassword`. If `sessionUserID != targetID`, skip current password check (admin override). Validate `new_password == confirm_password`. Hash and update.

   All POST handlers: check `HX-Request` header. For htmx: use `HX-Redirect`. For non-htmx: use `http.Redirect(w, r, url, http.StatusSeeOther)`. Always set flash message before redirect.

   Get session user ID from session manager: read the session key used in login.go (likely `"user_id"` — verify by reading `internal/auth/session.go` or `internal/admin/login.go`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> user management handlers | Untrusted input for user creation/editing |
| session -> password change | Self vs admin-override authorization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03 | Elevation of Privilege | Password change without current password | mitigate | Self-change requires current password verification via `auth.VerifyPassword`. Admin override only when `sessionUserID != targetID`. |
| T-05-04 | Denial of Service | Delete last admin | mitigate | Cannot delete self. `countAdmins` check before delete of any admin user. |
| T-05-05 | Elevation of Privilege | Demote last admin | mitigate | Before role change from admin->editor, verify `countAdmins() > 1`. Reject with flash error if not. SQLite single-writer serializes concurrent attempts. |
| T-05-06 | Spoofing | CSRF on user management forms | mitigate | All POST routes wrapped in gorilla/csrf middleware (established in Phase 2). Forms include CSRF hidden input. htmx sends via hx-headers on body. |
| T-05-07 | Tampering | Role value injection | mitigate | Validate role is exactly "admin" or "editor" before INSERT/UPDATE; reject any other value. |
</threat_model>
