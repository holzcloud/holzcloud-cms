<objective>
Build the reusable container recipe in `deploy/test/` and prove UNIT-01: the unchanged
`deploy/holzcloud.service` starts under a real systemd (PID 1 of a Debian container) and the site
answers HTTP. Add the enforcement canary that tells every later step whether this container
enforces seccomp at all.

Purpose: Phases 21 and 22 reuse this recipe (D-02), and plan 20-02 can only call a
`MemoryDenyWriteExecute` result evidence if the canary says the filter was really there. The
research measured that linux/amd64 under Rosetta installs no seccomp filter (`Seccomp: 0`), so a
green plugin run there would prove nothing about MDWE.

Output: `deploy/test/Dockerfile`, `deploy/test/Dockerfile.dockerignore`, `deploy/test/run.sh`
(subcommands build, up, start, wait, canary, exec, logs, down, smoke), `deploy/test/canary/`
(own Go module, stdlib only), one line in `.gitignore`.

The run.sh interface is a contract that plans 20-02 and 20-03 extend and phases 21 and 22 script
against. Environment variables: PLATFORM (default linux/amd64), BASE_IMAGE (default
debian:bookworm-slim), TARGET (default unit-test, other value systemd-base), IMAGE, NAME,
OUT_DIR (default deploy/test/out/ plus the architecture, gitignored scratch), KEEP, READY_TIMEOUT
(default 120), DOCKER_RUN_ARGS, VERSION, COMMIT. Exit codes: 0 ok, 1 failure, 2 usage, 3 "ran, but
the platform cannot give the evidence".

Decision coverage: D-01 (measure on linux/amd64 via emulation, name the caveat), D-02 (recipe in
deploy/test as Dockerfile plus run.sh; systemd Debian image; privileged run; build/start/exec
separable). The user's post-research refinement of D-01 (one narrow native arm64 run, only as
MDWE evidence) is used here for the platform banner and the canary; the arm64 evidence run itself
is plan 20-02.

Pitfalls carried from the research: Rosetta installs no seccomp filter (a pass there is a false pass), and `PrivateTmp=true` hides /tmp from the transient unit, so the probe lives in `/usr/local/bin`.

**deploy/test/canary/go.mod.** `module hc-canary`, `go 1.24` (the version the plugin modules use), no require lines: stdlib only, no module dependency is added to the repository, and because it is its own module the root `go vet ./...` and `go mod tidy` do not see it.

**deploy/test/canary/main.go.** `package main`, English comments, gofmt-clean (CI runs `gofmt -l .` over the whole tree, nested modules included). Comments name symbols and files, never a `file.go:123` line citation (the `tools/cites` gate refuses the form). It prints one line per probe, the label padded to 22 columns, then `ALLOWED` or `denied (` plus the error text plus `)`. Labels exactly, in this order: `mmap RW`, `mprotect RW->RX`, `mmap RWX`, `socket AF_NETLINK`, `socket AF_INET`, `stat /proc/sys`, `stat /dev/kmsg`, `write /etc`. Implementation with package `syscall` and `os` only: anonymous private `syscall.Mmap` with PROT_READ|PROT_WRITE (unmap afterwards); the same mapping then `syscall.Mprotect` to PROT_READ|PROT_EXEC; an anonymous mapping asking PROT_READ|PROT_WRITE|PROT_EXEC at once; `syscall.Socket` with AF_NETLINK/SOCK_RAW and with AF_INET/SOCK_STREAM (close on success); `os.Stat` of `/proc/sys` and `/dev/kmsg`; `os.OpenFile` of `/etc/hc-canary-probe` with O_CREATE|O_WRONLY (remove it if it opens). Afterwards print, verbatim, every line of `/proc/self/status` that starts with `Seccomp` (those read `Seccomp:` and `Seccomp_filters:`). The probe always exits 0: a denial is the measurement, the verdict belongs to run.sh.

**deploy/test/Dockerfile.** Add a stage `canary` between `build` and `systemd-base`: `FROM --platform=$BUILDPLATFORM golang:${GO_VERSION} AS canary`, the same TARGETOS/TARGETARCH defaults, `COPY deploy/test/canary/ ./`, and `CGO_ENABLED=0 GOOS=${TARGETOS} GOARCH=${TARGETARCH} go build -trimpath -ldflags="-s -w" -o /hc-canary .`. In stage `unit-test` copy it from stage `canary` to `/usr/local/bin/hc-canary`. `unit-test` stays the last stage.

**deploy/test/run.sh, subcommand `canary`** (per D-01: this is how the emulation caveat is measured rather than asserted). Require the service to be active (`systemctl is-active holzcloud`) and say to run `start` first, because `start` decides whether the ProcSubset drop-in exists. Build the property list from the unit's own sandbox lines: User=holzcloud, NoNewPrivileges=true, ProtectSystem=strict, ReadWritePaths=/opt/holzcloud/data, PrivateTmp=true, PrivateDevices=true, ProtectProc=invisible, ProcSubset (value `all` when `/etc/systemd/system/holzcloud.service.d/container.conf` exists in the container, else `pid`), RestrictNamespaces=true, RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX, LockPersonality=true, CapabilityBoundingSet= (empty), and the two SystemCallFilter lines `@system-service` and `~@privileged @resources`. Run `systemd-run --wait --pipe --quiet` with one `-p` per property twice: first with `MemoryDenyWriteExecute=yes`, then with `MemoryDenyWriteExecute=no` as a control. Write both outputs to `$OUT_DIR/canary.txt` under the headers `== MemoryDenyWriteExecute=yes ==` and `== MemoryDenyWriteExecute=no (control) ==` and print them. Verdict rules, in this order: (1) the control must show `ALLOWED` on both the `mprotect RW->RX` and the `mmap RWX` line, otherwise the probe is invalid (denied for some other reason): print `CANARY INVALID` and exit 1. (2) In the `yes` section, if either of those two lines says `ALLOWED`, write `not-enforced` to `$OUT_DIR/canary.verdict`, print `SECCOMP NOT ENFORCED - MDWE verdict is void on this platform` and exit 3. (3) Otherwise write `enforced`, print `SECCOMP ENFORCED` and exit 0. Also print which mount-namespace probes were denied, so the report can say mount-namespace directives are enforced even when seccomp is not.
