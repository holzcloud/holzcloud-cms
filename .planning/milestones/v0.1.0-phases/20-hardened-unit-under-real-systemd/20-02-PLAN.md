<objective>
Prove UNIT-02: every shipped wasm plugin loads and runs under the hardened unit, and settle the
`MemoryDenyWriteExecute=true` versus wazero suspicion with evidence (D-03).

Purpose: The research refuted the suspicion as a failure and confirmed it as a silent downgrade.
wazero's default runtime config probes by mapping memory RW then mprotect to RX; under enforced
MDWE the probe fails and wazero silently uses its interpreter, so all five plugins still load and
run. That result is only valid where seccomp is really enforced. This plan builds the seed, check,
control and verdict steps and runs them on linux/amd64 (functional evidence; the verdict comes out
VOID under Rosetta) and on one narrow native arm64 run (the MDWE evidence).

Named deviation from D-01 (user decision after research, 2026-10-12): D-01 said linux/amd64 via
emulation only, no arm64 counter-run. Measured reason: amd64 under Rosetta installs no seccomp
filter (`Seccomp: 0`; a probe under MemoryDenyWriteExecute=yes was allowed mmap RWX and
mprotect RW->RX), so MDWE cannot be judged there. UNIT-01 and UNIT-03 stay on linux/amd64; the
arm64 run (`PLATFORM=linux/arm64`) exists only as MDWE-vs-wazero evidence. No native amd64 CI run
is planned.

Output: run.sh subcommands `seed`, `check`, `mdwe-control`, `verdict`, `mdwe` (the narrow run:
build, up, start, canary, seed, check, mdwe-control, verdict), and a comment above
`MemoryDenyWriteExecute=true` in the unit (user decision 2, no behaviour change).

Decision coverage: D-03 (measure both variants, unit unchanged first, adjust only if forced, no
pre-emptive removal, evidence = every plugin loaded and invoked); D-01 (named deviation above).
</objective>
