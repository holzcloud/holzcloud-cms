# Milestone audit: v2.5 — On the Phone

Opened and closed 2026-09-17. One phase (19), four plans, five requirements.
All five closed, none deferred.

Asked for in one sentence: **„die webapp soll komplett auch auf dem handy
nutzbar sein"**. The scope was settled the same day with the first measurement
in hand — all of it — and it is the scope that shipped.

---

## The five requirements, one by one

### PHONE-01 — no admin screen is wider than the phone ✅

Seven were. All twenty-nine now measure 0, and 0 boxes that no scrolling
ancestor holds.

**The survey's stated cause was wrong on six of the seven.** It read the
stylesheet and concluded that the container query which makes a table's card
scroll never applies. Asked in the browser: it applies, the card computes
`overflow-x: auto`, and it scrolls — 636 against 356 on the Websites screen.
What ran out of the card was a `.sr-only`: `position: absolute` with no
positioned ancestor, so its containing block is the page and it lands at its
static position out in the wide part of the table. The page then reached
exactly as far right as that invisible label stood — Users 275/665, Pages
187/577, Languages 97/487, Websites 50/440, Menus 41/431. One line,
`position: relative`, took all five to 0.

The Activity log (338) was the one real case of the suspected cause. Website
settings (59) was a flex row of a domain and two buttons with no `flex-wrap`.

### PHONE-02 — every control at least 44 × 44 ✅

462 controls under the minimum across the twenty-nine screens; 0 now. Thirteen
rules, one template line, no colour, spacing or typeface touched.

Hung on `(pointer: coarse)` rather than a width: the number is about fingers.
One stated exception, a tick box at 24 × 24 — WCAG 2.2 SC 2.5.8's minimum, and
nearly four times the measured 13 × 13 — sitting in a 44px row that switches
with it.

### PHONE-03 — every typing field at least 16px ✅

16 → 0. Once the tick boxes came out of the list — which this requirement's own
last sentence had already asked for and the first survey had not done — exactly
one field was left: the page editor's writing box, at 14px.

### PHONE-04 — the measurement is repeated and committed ✅

`v2.5-PHONE-SURVEY-AFTER.txt` beside `v2.5-PHONE-SURVEY.txt`, the full reading
in `milestones/v2.5-phases/19-on-the-phone/19-AFTER.json`. 1048 → 0, 86 → 0, 462 → 0, 16 → 0.

### PHONE-05 — driven by hand in a phone-shaped browser ✅

Eight things a measurement cannot see. It found two, and both were real. See
below.

## What this milestone is actually about

Every defect in it was in a rule that **looked right in the file**. Not one was
a missing rule.

- The card scroll worked; an invisible label escaped it.
- The narrow-screen row-menu rule had never run once since it was written,
  because `@layer components` beats `@layer layout` whatever the specificity.
  Its comment described the fault it was preventing, precisely, and it was
  preventing nothing. The last row's menu — publish, duplicate, delete — was
  cut off 22px below its card.
- `.card:has(> #page-list)` listed the containers it knew by name and had never
  been told about `#activity-list`.
- `class="checkbox-label"` was a name no stylesheet defines, used once, where
  `.form-check` was the name everywhere else. That one screen was the last one
  failing PHONE-02.
- A `min-inline-size` a flex row silently took back: the tick box was set to 24
  and measured 14.
- And one the phase made itself, an hour before the pass caught it:
  `display: grid` on the hamburger, written to centre an icon, beat the layout
  layer's `display: none` and put a drawer handle beside an open drawer on a
  touch laptop.

None of these fails a test. Nothing throws, nothing 500s, every screen answers
200. The page simply looks wrong to somebody holding it. **That is what the
browser pass is for**, and v2.4 — where it found nothing for the first time —
is the exception that makes the point rather than the rule.

## The instrument was wrong three times, and each time measuring said so

A tool that answers "nothing found" is worth exactly what its questions are
worth. Three of the first survey's were wrong, and two of the hands-on pass's
own:

1. `window.innerWidth` grows with the fault — Chrome's phone emulation rescales
   an overflowing page instead of letting it scroll, so the Users screen
   reported 665 at a 390px viewport. `documentElement.clientWidth` is the ruler
   that holds still.
2. A box a scrolling ancestor holds is not a box a person has to chase. The
   first reading counted the cure as the disease, and had to be taught to walk
   **every** scrolling ancestor, because an `<svg>` clips its own contents.
3. A closed `<details>` does not give its contents `display: none`; Chromium
   hides them with `content-visibility` and they go on reporting a box.
4. `form button[type="submit"]` finds the sign-out button in the folded user
   menu before the editor's save button.
5. Reading `.rowmenu-menu` without opening anything measures a closed box and
   answers nothing — it said "on screen" while the real menu sat 298px outside
   the card.

Cost: one stylesheet, one template line. No new dependency, no build step, no
second stylesheet, no separate mobile application. The constraint against build
tools has now held for six milestones.

## What was deliberately not done

Not the public themes. A visitor's side of the eight shipped themes is a
different question with a different audience, and it was out of scope from the
first sentence of the requirements.

Not a redesign. Every rule added is a minimum; none changes something already
big enough, and none sets a colour, a spacing or a typeface.
