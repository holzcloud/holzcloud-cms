<objective>
The half of this phase that would have been wrong, and would have been wrong
quietly.

**Block HTML is rendered once, on save, and stored.**
`internal/admin/page_blocks.go:74-81` says so in its own comment: pictures are
looked up where the media store is, handed to the renderer as plain values, and
"a block page is rendered once on save rather than on every visit". The public
side then only *rewrites* what it reads — `snippet.Expand` at
`pagedata.go:32`, `filterByPlugins` at `:36`, `h.responsive` at `:40`.

So an album expanded at save time makes GAL-03 **false**: "changing the album
changes every page that carries it, without touching those pages" would simply
not happen, the pages would keep serving a frozen copy, and **nothing anywhere
would report it**. There is no test that fails, no error in a log, no warning in
a report. The editor changes the album, reloads the page, and sees the old
pictures.

**The only late-binding mechanism in this tree is `snippet.Expand`**
(`internal/snippet/store.go:243-264`), and `internal/public/pagedata.go:22-25`
gives the reason in exactly these terms: "Baking the expansion into content_html
on save would freeze a copy of the opening hours into every page, which is the
thing snippets exist to prevent." An album is the same sentence with pictures
instead of opening hours. So a gallery block naming an album renders to a
**marker** at save time and is expanded in `pageContent` at request time,
between `snippet.Expand` and `h.responsive` — the ordering matters, because the
`<img>` tags the expansion produces must still be seen by
`media.MakeResponsive`.

**One thing is copied from `snippet.Expand` and one thing is deliberately not.**
Copied: the marker survives into `content_html` and is replaced per request.
Not copied: its loading strategy. `loadSnippets` builds a map for the *whole
website* on every request; a website with fifty albums must not load fifty to
render one page. The strategy is `media.LoadImageSets`' instead
(`variant_store.go:176`), whose comment states the rule — "Only the files
actually named in the HTML are looked up".

**And there is a trap under all of it that neither planning document names.**
`block.Block.Empty()` reports a gallery as empty when it has no items
(`block.go:245-256`), and `Set.Clean` drops every empty block before encoding
(`block.go:315-330`). A gallery block that names an album has no items. **So,
unfixed, the block is deleted by the very save that creates it** — the editor
picks an album, saves, and the block is gone, with no message. That is a task in
this plan and it is gated.

Purpose: GAL-03 in full, and the source half of GAL-07.
Output: an album placed on several pages, changed once, and every page carrying
it changed with it.
</objective>

**`internal/album/expand.go` — the marker, the reader and the expander.**

The marker's literal spelling, its regular expression and the function that
writes it all live here (or all in `internal/block`, per task 1's cycle check —
one file either way).

- `UsedSlugs(html string) []string` — the slugs a document names, deduplicated,
  mirroring `snippet.UsedKeys`. This is what turns "load what the page names"
  from an intention into a query.
- `Expand(html string, set Set) string` — replaces each marker with the rendered
  gallery, calling `block.GalleryItems(at, items, look, t)` with the position the
  marker carries. A marker whose slug is not in the set expands to the empty
  string, for the reason `snippet.Expand` gives: a visitor must not see the
  internal syntax on a live page. Return the input unchanged when it contains no
  marker at all, exactly as `snippet.Expand:252` does — that early return is
  what keeps the cost of this mechanism zero for the pages that do not use it.
- `Set` — what one request needs: the items per slug, the images they name, and
  the translator. Give it a `Lookup()` method returning a `block.Lookup` closed
  over the image map, so `internal/public` does not grow a second copy of
  `admin.blockImages`.

**`internal/album/store.go` gains `LoadFor(ctx, websiteID int64, html string,
t func(string) string) (Set, error)`** — one method, doing the whole loading in
the `LoadImageSets` shape: read the slugs out of the HTML, return an empty set
immediately if there are none, then **one** query for the album items joined to
their media rows, with the slugs as bound placeholders and `website_id` in the
`WHERE`. The comment states the rule it is copying and names
`variant_store.go:176`, and states what it deliberately does not copy: a
per-website map, which is what `loadSnippets` builds and what would make a
website with fifty albums pay for fifty to render one page.

The join is where the website scoping and the media resolution meet, so it is

for the album **and** require the media row's `website_id` to match, because a
media row could in principle have been attached before a check existed. Say that
in the comment rather than leaving the second condition looking redundant.

**The defect.** Neither `11-CONTEXT.md` nor `11-PATTERNS.md` notices that

**The decisions.**

1. **The marker carries the block's position and the wrapper is written at
   save.** §A.3 says only that the block "must render to a marker". Which parts
   are late and which are not is decided here: the columns and the display are
   properties of the block and known at save; the pictures are the album's. The
   position rides in the marker because D-03's fragment ids are minted from it.
