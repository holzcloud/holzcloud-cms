<objective>
Close the two guards a genuinely multi-valued field needs, and carry the marker
into a group's rows.

Plan 07-01 made three values arrive as three values. This plan makes an
over-long or over-numerous set say so instead of quietly becoming something
smaller. `MaxValueBytes` is now shared across all of one field's values, and the
one place that used to shorten a too-long value did it silently — for a
multi-valued field that would cut a value in half, and neither the author nor the
theme would ever learn that it happened.

The second half is the marker inside a group. `fieldsFromRequest` has a twin line
for a group's rows, and a `mehrfachauswahl` inside a group would hit it and keep
only the first ticked value. The fix is the same one D-03 already chose: the
marker is minted in one place, never spelled out at a call site.

Purpose: make the encoding honest under pressure, and complete on both of its
two paths.
Output: `max_werte` enforced, the shared budget reported, and group rows carrying
the marker.
</objective>

bundle and AI round trip". Plan 07-02 paid the bundle half for all four new
definition properties. This is the other half, and it is the smaller one: an
assistant already learns a field's kind from `art`, so nothing here teaches it a
new vocabulary. What it cannot learn today is the shape of an acceptable value —

number outside its bounds, and above all that a field taking several values still
arrives through a `map[string]string`, so the several values have to be spelled

**`internal/ai/tools.go` — `felderAuflisten`'s per-field map.** Add, each only
when it carries something:

  omitted when it is the dropdown every existing field already is;

  set — "no bound" and "the bound is zero" are different facts, which is the same
