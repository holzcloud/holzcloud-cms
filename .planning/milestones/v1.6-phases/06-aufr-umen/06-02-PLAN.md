<objective>
Prove — end to end, on a real `ubuntu-latest` runner — that a
`GOOS=wasip1 GOARCH=wasm` build is byte-identical across hosts, before any later
plan commits roughly 21 MB of rebuilt binaries against that assumption.

Purpose: D-05 is the one question the research could cite but not falsify; its
container never got past the registry pull, so the host axis is `[CITED]` and not
`[VERIFIED]`. Everything downstream — the rebuild commit, the blocking `-check`
step, the skip promotion — is worthless if the cross-host hash does not hold, and
each of those is expensive to undo. So the thinnest possible slice runs first:
one command, one path through the tool, the `os/exec` build, the hash and CI.

Output: a working `tools/wasm` in `-print-hashes` mode; a temporary CI step; and a
recorded PASS or FAIL verdict on cross-host reproducibility.

**Runs in wave 2 alongside `06-03` and `06-04`.** Their file sets are disjoint from
this one, and every git assertion in all three is path-scoped rather than
HEAD-relative, so three plans writing into one worktree cannot make each other's
verifications fail.
</objective>

  <action>
Create `tools/wasm/main.go` as a single-file `package main`, following the house
shape of its two siblings: `// Command wasm …` opening line, an indented block of
invocation lines, then prose explaining why the tool exists. **Comments in
`tools/` are English; user-facing stdout is German.** Errors exit through a
package-level `fail(err error)` that writes `error:` and the error to stderr and
calls `os.Exit(1)`; a bad flag combination exits 2 with a usage line. Not `slog`,
not `log.Fatal`.

Declare the six targets as a compile-time slice of struct values, each carrying the
module directory relative to the repository root and the output path relative to the
repository root: `plugins/bestellung`, `plugins/jahreszahl`,
`plugins/kontaktformular`, `plugins/nicht-gefunden`, `plugins/suche` each producing
`plugin.wasm` beside their directory, and `internal/plugin/testdata/echo` producing
`internal/plugin/testdata/echo.wasm`. A short name per target (`bestellung`,
`jahreszahl`, `kontaktformular`, `nicht-gefunden`, `suche`, `echo`) is what a
positional argument selects.

Declare the toolchain pin as a package-level constant set to `go1.26.6`, with a
comment stating that it must be greater than or equal to the `go` directive in the
root `go.mod` because `echo` lives in the root module, and that the go command
refuses to load a module declaring a higher minimum than the running toolchain.
Use the bare form, never `go1.26.6+auto`, because `+auto` selects a newer version
as needed and defeats the pin.

The doc comment must also record, in prose, why `-buildvcs=false` is present: it
removes `vcs.revision`, `vcs.time` and `vcs.modified` from the guest, which is a
deliberate reduction in provenance metadata, taken because the commit containing the
artifact is its provenance and because the stamps make the byte comparison
impossible by construction. Say it plainly enough that nobody re-enables stamping
later for traceability and silently breaks the comparison.

Implement one build function taking the repository root, a target and a destination
path. It runs `go build` through `os/exec` with `cmd.Dir` set to the module
directory and an environment built explicitly rather than inherited: `GOOS=wasip1`,
`GOARCH=wasm`, `CGO_ENABLED=0`, `GOTOOLCHAIN` set to the pin constant, and empty
assignments for `GOFLAGS` and `GOEXPERIMENT` so an inherited value from a
contributor's shell cannot change the bytes. Arguments in order:
`-buildmode=c-shared`, `-trimpath`, `-buildvcs=false`, `-ldflags=-s -w` as a
**single** argument (literal quotes would reach the linker), `-o` with the
destination, and `.`. Wire `cmd.Stdout` and `cmd.Stderr` to the process's own so a
compile error is visible.

Flags in `main()`, declared with `flag`: `-root` (string, default `"."`, the
repository root, matching `tools/i18n`), `-print-hashes` (bool), `-check` (bool)
and `-out` (string). This task implements `-print-hashes` only. `-check` and `-out`
are declared and, when passed, exit 2 with a usage line saying they are not yet
implemented — Task 1 of plan 06-05 fills them in. Positional arguments after the
flags select targets by short name; with none, all six run. An unknown name exits 2.

`-print-hashes` builds each selected target into `os.MkdirTemp` and never touches
the working tree. For each target it prints one German, column-aligned line to
stdout in the register of `tools/i18n/main.go:112`, carrying the short name, the
sha256 in hex, the size in bytes and the Go version embedded in the built module.
Recover the embedded version by scanning the built bytes for the first `go1.` run
matching a version pattern — a plain byte scan, not a wasm parser — because
"the pin moved" and "the source changed" are the two causes of a hash mismatch and
the message must let a human tell them apart at a glance. Compute the hash with
`crypto/sha256` plus `encoding/hex` over the built file, reusing the shape of
`hashFile` in `tools/mkbundle/main.go:322` rather than the function itself.

Then add a **temporary** step to the `test` job in `.github/workflows/ci.yml`,
placed after `Vet` and before `Build`, named
`Cross-host hash falsification (temporary — remove in plan 06-06)`, running
`go run ./tools/wasm -print-hashes`. Above it put a German `#` comment in the
register of `ci.yml:56–58` explaining that the step exists to compare the six
hashes produced on the runner against the six produced on a developer machine, and
that it is deleted once the comparison is made blocking. Add no action, change no
`env:` block, and touch nothing else in the file.

Run `gofmt -w tools/wasm/main.go` before committing; `ci.yml`'s `Verify formatting`
step fails the whole job on an unformatted file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → `go` subprocess | `tools/wasm` invokes the host `go` toolchain with an environment it constructs; an inherited `GOFLAGS` or `GOEXPERIMENT` would cross this boundary and change the produced bytes |
| `GOPROXY` / toolchain module download → build host | the pinned `GOTOOLCHAIN` is fetched as a module from a network service |
| committed `.wasm` artifact → CI green signal | the artifact attests to source it may not have been built from |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-02 | Tampering | `GOTOOLCHAIN` module download | medium | transfer | Go's checksum database verifies toolchain module downloads; `GOSUMDB=off` makes such a download fail rather than proceed unverified (go.dev/doc/toolchain). No repo change needed |
