<objective>
Give existing websites the way to the current privacy template without touching a single page they already have, and write the phase down where an operator and a reader of the release will look (DSV-07; decisions D-06 and, for the documents, D-03 to D-05, D-08, D-10).

Purpose: websites created before this phase carry a starter privacy page that says the site sets no cookies, and some of them have a shop. D-06 forbids changing those pages. What the operator needs is to be told, on the screen they already use for the website, that the template has moved on, and to get the new text next to the old one as a draft, to compare and copy from. The documents must stop saying "two exceptions" and must name the third cookie, the log and the limits, or the release repeats the mistake it fixes.

Output: `HandlePrivacyDraft` and its route; the Privacy statement card on the website settings screen; the catalogue entries; the rewritten cookie section of `docs/security.md`; a paragraph in the CHANGELOG entry of 0.1.1; and the phase's closing gates.

Scope: the card and the button only (D-06). No form per website for the responsible body or the providers, no change to `internal/activity`, no change to an existing page, no extension of the readiness checklist of the settings screen (it feeds the dashboard and the assistant interface, and a privacy page that exists is not a launch blocker the checklist can judge).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor browser to the admin route | a state-changing POST reaches the server with a session |
| website id in the path to the data of another website | an editor is restricted to some websites |
| stored page content to the settings screen | the hint must not display content an editor wrote |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
