<objective>
Secure the EXIF removal the audit found already in place, by a regression test through the path an upload really takes, and by a guard that keeps it the only path (DSV-05; decision D-10).

Purpose: `Intake.Keep` strips metadata before a byte reaches the disk, and `StripMetadata` is well covered by unit tests (`strip_test.go`, `orient_keep_test.go`). What no test does is call `Check` and `Keep` themselves with a photograph that carries GPS and camera data: `TestPrepareUploadRemovesMetadataBeforeStoring` calls `PrepareUpload` and `StoreFile` directly with a toy payload, and `TestProfileSurvivesKeep` is named for `Keep` but calls `StripMetadata`. A refactor that moves the strip out of `Keep`, or a second path that stores bytes, would leave every existing test green. The phase promise that "a photograph taken at home does not publish the home address" needs a test at that seam.

Output: two new test files in `internal/media`. No production code changes: the audit found the behaviour correct (D-10 asks for the regression test only).

Scope: no new function, no change to `intake.go`, `strip.go` or `scale.go`. No fixture is added to the repository as a binary file; every fixture is built in the test from the helpers that already exist in the package.
</objective>
