<objective>
Change the shipped `deploy/backup.sh` so that it repeats an `rsync` that ends with status 24 once and ends the night loudly, with status 24, if that recurs; and so that a night that fails before its `MANIFEST` is written removes the directory it made (ROB-01, ROB-02). Prove both with a hermetic test that needs neither Docker nor root.

Purpose: the owner decided on 2026-10-26 (see the note in `.planning/REQUIREMENTS.md`) that a file vanishing during the copy should not cost the night at the first occurrence, and that a half-written directory must no longer sit on a nearly full filesystem and make the guard refuse every later night. Phase 25 measured both problems (8 of 40 refused with status 24; a 1098915817-byte directory without MANIFEST that blocked the next night). This plan is the script; plans 29-02 and 29-03 teach the harness to assert the new behaviour, 29-04 makes the evidence set on the changed script.

Output: the changed `deploy/backup.sh`; the new `deploy/test/backup-robust.sh`; a Phase 29 section in `deploy/test/README.md`.

Hard limits for the whole phase, repeated here because they bind this plan: no `git push`, no tag, no `gh workflow run`, no `gh` call that writes, no change to `deploy/DEPLOY.md`, `deploy/restore.sh`, `deploy/holzcloud-backup.service`, `deploy/holzcloud-backup.timer`, `deploy/test/run.sh`, `deploy/test/native-amd64.sh`, `.github/`, or any earlier record under `deploy/*-RUN.md` and `deploy/SECURITY-SCORE.md`.

## The contract that later plans read (fixed here; do not vary the strings)

Design choice C-1: one function `run_rsync WHAT RSYNC_ARGS...` is the only place in `deploy/backup.sh` that starts `rsync`. WHAT is a short phrase for the messages: the directory name (`media`, `templates`, `plugins`, `sprachen`, `marke`) for the loop of step 3, and the words `the off-site copy` for step 6.
Design choice C-2: the three message lines, all on stderr, with the exact text below (the harness greps `rsync exited 24` and `removed `):
- repeat: `WARNING: rsync exited 24 (files vanished) while copying ${what}; repeating it once`
- recurrence: `ERROR: rsync exited 24 again while copying ${what}; giving up`, then the script exits 24
- cleanup: `ERROR: backup did not finish; removed ${OWN_DIR}, which had no MANIFEST`
- cleanup that failed to remove: `ERROR: backup did not finish and ${OWN_DIR} could not be removed; it has no MANIFEST and restore.sh refuses it, remove it by hand`
- refusal to start: `ERROR: ${BACKUP_DIR} exists already; refusing to start so that no earlier backup is touched`, then exit 1
Design choice C-3: `OWN_DIR` is empty until this run's own `mkdir` of `BACKUP_DIR` has succeeded; the cleanup acts on `OWN_DIR` only.
Design choice C-4: the MANIFEST is written to `${BACKUP_DIR}/MANIFEST.partial` and renamed to `${BACKUP_DIR}/MANIFEST`; its four keys and their order stay as they are.
Design choice C-5: every other line the script prints, and the line `MIN_FREE_MB="${MIN_FREE_MB:-1024}"`, stay byte-identical to HEAD, because `deploy/test/nightly.sh` reads them (step_span, the consist transcripts, capfull_run).
Design choice C-6: the cleanup decides by the absence of `MANIFEST`, never by `$?`: inside an EXIT trap that runs because of SIGTERM, bash reports `$?` as 0 (measured on bash 3.2.57, macOS) and then exits 143; the trap must not call `exit`, so bash keeps the original status.
Limit named, not solved: SIGKILL (including the kernel's out-of-memory kill) and a power loss cannot be trapped; a directory without MANIFEST can still remain after them.
