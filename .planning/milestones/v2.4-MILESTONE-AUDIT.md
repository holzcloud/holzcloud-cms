# Milestone audit: v2.4 — What Has Accumulated

Opened 2026-09-15, closed 2026-09-17. Two phases, seven plans, eighteen commits.

**Thirteen requirements, thirteen met, none deferred.**

---

## What it was for

Not a feature milestone, and deliberately so. Three milestones in a row had
changed what the program *says*; this one changed nothing an operator can see.

It exists because the window ledger was empty for the first time since v1.10 —
and an empty ledger is not a clean tree, it is a tree with nothing left that
somebody wrote down. So the stock-take looked at what the ledger was never
watching.

## What the stock-take found, and the surprise is still at the top

The tree was in better shape than a cleanup milestone assumes: zero TODO, zero
FIXME, zero skipped tests, every documented invariant still true. What it had
accumulated was the four things a working tree accumulates without anybody
deciding to.

| Finding | Requirement | Outcome |
|---|---|---|
| 108 comments citing a line number, 45 already drifted | DOC-01 | **zero citations** — `tools/cites -check` refuses the form itself, and CI runs it |
| Comments describing fixed defects as open | DOC-02/03 | four corrected rather than deleted, because a corrected claim carries evidence the rule worked |
| 301 of 1312 exported names used nowhere outside | SURF-01/02 | 268 of 986, with `go run ./tools/surface` to reproduce the count |

## The finding the milestone did not go looking for

**Eleven defects, and every one of them was found by writing a test for a
screen — not by reading the code, not by a tool, and not by a browser.**

That is worth stating plainly because it is the argument TEST-01 was written to
make, and the milestone made it accidentally. Four of the eleven would have hurt
an operator:

- a domain removable through the wrong website's screen — a customer's site off
  the air, while the screen said "Domain removed";
- three products counting as zero products and as three pages, which silenced
  the warning that a deleted kind leaves its entries behind;
- a menu able to make itself unreachable while answering "Menu saved";
- an SVG check that claimed to refuse active content and refused four spellings
  of it.

Five more were sentences that never reached the translation catalogue — not
missing from it, *unknown* to it, so the gate reported neither open nor
orphaned. Two of those were still German on a program whose source language has
been English since v2.0.

## The finding under that one

**Three faults in the test harness itself**, each of which had made a whole
class of test impossible without anybody noticing:

- the loader had a nil template resolver, so no admin test could see which theme
  a website runs;
- `Argon2Params` was the zero value, so every password path **panicked** instead
  of failing — broken for exactly as long as it was unused;
- the loader had no wording resolver, so a word saved on that screen could never
  reach a rendered page.

A harness nobody exercises is not neutral. It quietly decides which tests can be
written.

## The lesson, because it caught the work fourteen times

**A second guard one layer down, or a catch-all arm, makes the first guard's
removal invisible.**

`Load` re-trims what `clean` trimmed. `NormalizeDomain` re-refuses what the
screen refused. `time.Parse("")` fails where the "no date" guard already did.
"Saving failed." answers for every unrecognised error. Each time, the test
passed while the guard was gone. Each time, the fix was the same: assert the
sentence the operator reads, or the number they see — never "an error came
back".

164 mutations were run across the phase and 158 were caught. The six survivors
are recorded at their own tests, each with the measurement showing it is
equivalent rather than missed.

## What was added that nobody asked for

One gate. `tools/assembled` refuses a sentence built with `fmt.Sprintf` inside a
call that shows its argument to an operator — the hole CLAUDE.md names in the
same breath as the rule. Its first draft found 185 things of which about seven
were real, because Content-Security-Policy is assembled from eight fragments
that read like prose to a crude test; it was narrowed to the shape with no false
positives, and its own comment says what it therefore cannot see. A gate that
cries wolf teaches people to waive it.

## QUAL-02, for the first time clean

Thirty admin screens driven in a real browser, then the four an operator only
reaches by doing something — because that is where all three of v2.3's interface
faults were. Nothing found. The import report's second heading, found by a test
this milestone, is confirmed gone in the browser too.

## What this milestone deliberately did not do

- It did not chase the coverage number into the long tail. Forty handlers are
  still at zero — the shop, two-factor enrolment, the CSV importer's inner
  panels, WordPress import, setup — and the requirement says why: a coverage
  number is not a goal, and the way to move it badly is to write tests that
  execute lines.
- It did not touch the public themes.
- It did not take the phone, which was asked for on 2026-09-17 mid-milestone.
  The ordering was put to the operator and the answer was to finish this one
  first; v2.5 is planned, measured, and waiting.
