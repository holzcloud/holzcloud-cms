# 16-01 — The five words are written as markers and resolved at delivery

Closes WORD-01, WORD-02, WORD-03 and window 34. Rests on 16-MEASUREMENT.md.

---

## §1 The decision the measurement makes

Candidate C′: the renderer writes a marker where it used to write a word, and
one guarded pass over the finished body replaces the markers with the words of
the page's language.

The measurement rules out candidate D (re-render per request: 124 µs and 215 KB
on a medium page, and unguardable) and rules out an unguarded C (37 µs and a
copy of every page into the garbage collector). C′ costs a page with no marker
311 ns and no allocation — the same `strings.Contains` the album marker already
pays, and the two guards can be asked side by side.

## §2 The shape

`[[w:<key>]]`, five keys, in the same family as `[[album:…]]` and for the same
reason: one syntax an editor never sees, one place that expands it.

- `[[w:previous]]` `[[w:next]]` `[[w:close]]` — the lightbox controls
- `[[w:novideo]]` — the sentence between the `<video>` tags
- `[[w:gallery]]` — the scrolling region's accessible name

The marker stands where an escaped word stands today, in text content
(`<a …>[[w:next]]</a>`) and inside an attribute (`aria-label="[[w:gallery]]"`).
It needs no quoting in either: the replacement escapes the word it writes, so
the escaping moves from save to delivery and nothing else changes.

## §3 What stops translating at save

Today two translators exist and window 34 is the gap between them: `Set.T`,
built from `ws.Locale` in `internal/admin/page_blocks.go`, translates at save;
`albumsFor`'s translator, built from the same `ws.Locale`, translates at
delivery. A page carrying one gallery of each kind was kept consistent by
making both of them the *website's* language — which is why an album gallery
answers in the website's language rather than the page's.

The gap closes by deleting both. After this plan:

- `block.Render` writes markers unconditionally. `Set.T` and `Set.text` go.
- `GalleryWrapper` writes a marker; its `t` parameter goes.
- `album.Set`/`LoadFor` no longer carry a translator.
- `albumsFor` no longer builds one — window 34 is closed by subtraction, not by
  a second locale lookup.

One translator is left, at one place, and it is the page's:
`i18n.T(i18n.Lang(ctx), …)`. `public.LocaleMiddleware` already puts the page's
language there, and its own comment says why — *"the language belongs to the
page, not to whoever is reading it"* (PUB-01).

## §4 Where the resolution happens

`internal/block.ResolveWords(html string, t func(string) string) string`, guarded
by `strings.Contains(html, "[[w:")` exactly as `ReplaceAlbumMarkers` is guarded.

Called from every place a stored body reaches a reader:

| Caller | Language | Why |
|---|---|---|
| `public.pageContent` | the page's | the page |
| `public.expandForFeed`, the feed's scan text | the page's | a feed is a live public route |
| `public.expandForPlugin` | the page's | a plugin filters what a visitor sees |
| `admin.preview` | the operator's | it is the operator reading it |
| `ai/tools.go` page read | the operator's | same |

`pageContent` resolves **after** `album.Expand` (so a marker an album produced is
resolved too) and **before** `filterByPlugins` (which runs last so that it sees
the page as a visitor would).

The pages that merely copy HTML — `page_locale.go`, `page_bulk.go`,
`csvimport/row.go` — are not in the table and must not be: a copy that carries
markers is a copy that resolves correctly in its new language, which is an
improvement they get for free.

## §5 WORD-03, and why there is no migration

A body written before this plan carries the words, not the markers. It contains
no `[[w:` , the guard skips it, and it renders exactly as it does today — frozen,
as it has been. It heals on its next save. That is window 8's rule applied
again, and the reason the marker's fields were made optional there.

Nothing reads the stored HTML expecting a word, so there is no reverse problem.

## §6 What must be proved

1. A body with no marker comes back **identical** — same string, no allocation.
2. A page with an inline gallery and an album gallery answers in **one**
   language, and it is the page's.
3. A page stored before this plan renders unchanged, with its frozen words.
4. No public response contains `[[w:` — the page, the feed, a plugin's view.
   `pluginhost_marker_test.go` is the precedent and the place.
5. The five keys and the five catalogue entries stay in step: a key the resolver
   does not know must fail the suite rather than reach a page.
