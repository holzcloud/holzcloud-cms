# 16-02 — A plugin says its own name in the operator's language

Closes WIN-08, the last open requirement of v2.3.

---

## §1 What is wrong, precisely

`plugin.json` carries three strings an operator reads: `name`, `description`
and `admin.label`. They are shown on `/admin/plugins`, in the sidebar, and as
the title of a plugin's own screen. None of them is translated, and four of the
five shipped plugins write them in German — on a program whose source language
has been English since v2.0.

So an English operator's sidebar says **Bestellungen** and **Nicht gefunden**,
and the plugin list explains the search engine in German. The ledger has carried
this as "deliberately open" through v2.0, v2.1 and v2.2. Three milestones is
long enough: it is decided here.

## §2 The decision

**Translated**, and by the same rule the rest of this program follows: the
source sentence is the key, and the translation lives with the thing that minted
it.

A theme carries `lang/<tag>.json` beside its templates (TEMPLATE-SPEC §2.5). A
plugin carries its catalogue **inside `plugin.json`**, under `"lang"`:

```json
{
  "name": "Search",
  "description": "Full-text search across the published pages, at /suche.",
  "lang": {
    "de": {
      "Search": "Suche",
      "Full-text search across the published pages, at /suche.": "Die Volltextsuche über die veröffentlichten Seiten, unter /suche."
    }
  }
}
```

Inside the manifest and not in a `lang/` directory of its own, for one reason
that is about this case and not about taste: **there are three strings.** A
theme has dozens, spread across templates that are written at different times,
and a file per language is what keeps that readable. A plugin has a name, a
sentence and a menu label, and they are all declared in one file already. A
second file to hold three lines is a second file to forget — and the manifest is
what the host reads *before* the module exists, which is exactly when these
three strings are needed.

The key scheme is the theme's, unchanged: the source string is the key, a
missing key falls back to the source, and a plugin with no `lang` at all behaves
exactly as it does today.

## §3 Which language

**The operator's**, and this is the half of the question v2.1 got right for the
other half. `sdk.T` answers in the operator's language on an admin request and
in the page's language on a public one, because they are different questions.
These three strings only ever appear in the admin, so they are only ever the
operator's question.

`i18n.Lang(ctx)` on an admin request is already that language.

## §4 The work

1. `Manifest.Lang map[string]map[string]string`, plus `Text(lang, s)`,
   `NameIn`, `DescriptionIn` and `AdminLabelIn` on the manifest. One lookup, no
   locale logic anywhere else.
2. `AdminLink` carries the catalogue so the sidebar can resolve its label, and
   `WithNav`'s plugin function takes a `context.Context` — today it takes only a
   website id, which is why nothing there could know a language.
3. `/admin/plugins`, the plugin screen title and the flash after an install use
   the resolved strings.
4. The five shipped manifests are rewritten with English sources and `de`, `es`,
   `fr` and `it` catalogues, and their `.zip`s rebuilt by `go run ./tools/wasm`.
5. `sdk/plugin.go` — the document a plugin author actually reads — gains the
   section, and `docs/` stays as it is: there is no plugin spec file to update.

## §5 What must be proved

1. A manifest with no `lang` renders exactly as it does today.
2. An unknown language, and a known language missing one key, fall back to the
   source string rather than to the empty string.
3. The five shipped plugins carry all four languages for all three of their own
   strings, and no key that is not one of those three. A sixth plugin added
   without a catalogue fails nothing; a shipped one that forgets a language
   fails the suite.
4. The sidebar, the plugin list and the screen title answer in the operator's
   language — asserted in German and in one other, because a test that only
   checks German passes on a build that ignores the language entirely.
