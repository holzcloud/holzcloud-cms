<objective>
A sign-out that signs somebody out, and a Content-Security-Policy change that
this shape does not need.

`HandleLogout` (`internal/admin/login.go:128-136`) destroys the session and
redirects to `/admin/login`. For a session established through the identity
provider that is a sign-out that does not sign anybody out: the browser still
holds the authentik cookie, and the next click on anything under `/admin/`
carries a fresh set of identity headers from the outpost and signs the person
straight back in. SSO-08 is exactly this: *signing out signs the person out at
Authentik too, so the next click does not silently sign them back in.*

**The `form-action` trap, and why this plan does not spring it.**
`adminCSP` (`internal/web/headers.go:17`) carries `form-action 'self'`.
`HandleLogout` is a **POST**, and a redirect issued in response to a form
submission is checked against `form-action` by some browsers — Safari among
them. This codebase has already paid for that once and wrote the incident down
at `headers.go:41-53`: *"the TWINT payment on an iPhone dies silently at the
moment of the handover, and nothing in the server log says why."*

`ROADMAP.md`'s step ⑦ therefore names a fix: mirror `PublicCSP` /
`SecureHeadersWith` (`headers.go:59-67`, `:82`) as `web.AdminCSP` /
`web.AdminHeadersWith`, wired at both `main.go:1004` and `:1036`. **This plan
deliberately does not build it**, and the reason is measured rather than
stylistic: the outpost's `/outpost.goauthentik.io/sign_out` is routed on the
application's own domain and is therefore **same-origin**, and `form-action
'self'` permits a same-origin target. The trap fires only if a *separate outpost
host* is ever supported, and this phase does not support one. Building
`AdminCSP` now would add a mechanism with no caller, in the file whose whole
value is that its policies are short enough to read.

What replaces it is smaller and holds the premise the absence rests on: the
target is a **relative path**, built from the configuration and never from
`r.Host` or any header, and a test asserts that. If a later phase supports a
separate outpost host, that test fails and says exactly what has to change and
why — which is more than a `AdminCSP` nobody passes a second origin to would
have said.

Purpose: SSO-08, and the half of SSO-09 that is about the password path's
sign-out.
Output: one branch in one handler, one assertion about a leading slash, and a
recorded non-decision beside the incident that would have justified the other
choice.

    func (h *Handler) HandleLogout(w http.ResponseWriter, r *http.Request) error {
        // Vor dem Zerstören: danach weiss die Sitzung nicht mehr, wer gegangen ist.
        h.LogActivity(r, activity.Entry{Action: activity.ActionAuthLogout, EntityType: "user"})

        // Read before Destroy, for the same reason the line above is where it
        // is: after Destroy the session no longer knows how it was established,
        // and the branch below would silently always take the password path.
        target := "/admin/login"
        if h.cfg != nil && h.cfg.SSOEnabled &&
            h.sm.GetBool(r.Context(), auth.SessionKeyViaSSO) {
            target = h.cfg.SSOSignOutPath
        }

        if err := h.sm.Destroy(r.Context()); err != nil {
            return err
        }
        return h.redirect(w, r, target)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the browser's authentik cookie → the next request | Destroying the session here does nothing to that cookie. Until the outpost is told, the person is one navigation away from being signed back in. |
| a redirect target → the browser | A sign-out is the one redirect a person follows without reading. Whatever this handler puts in `Location` is where they go. |
| `form-action 'self'` → a redirect answering a POST | Some browsers check the redirect target of a form submission against `form-action`, and fail silently when it does not match. This codebase has been bitten by it once. |
