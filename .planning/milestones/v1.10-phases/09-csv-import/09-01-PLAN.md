<objective>
The half most likely to be wrong, built alone and proved alone.

`encoding/csv` has no limit anywhere: not on rows, not on cells, not on what a
NUL byte does. This plan writes the package that stands between an uploaded file
and everything else in the phase, and it writes it with no database, no HTTP and
no `internal/page` — so the whole hostile-file checklist D-08 … D-16 is a table
test rather than a browser session.

**Why this is wave 1 and why it is a horizontal layer rather than a tracer
slice.** GSD's default is to lead a phase with an end-to-end tracer. It is
deliberately overruled here, and the reason is concrete rather than stylistic:
`09-CONTEXT.md` fixes the build order, and its first step is this package,
"because it is the half most likely to be wrong". A tracer through the wizard
would prove the wizard — which `09-PATTERNS.md` §A shows has **no analog anywhere
in this tree** and is therefore invented — while leaving the parser, which has
nine independent named defences and one off-by-one that makes every message in
the phase wrong, unproved until wave 4. Proving the invented shape on top of an
unproved parser is proving the wrong half first. The order stands.

The off-by-one is the thing to get right here and nowhere else. Every requirement
in this phase that says „row number" — IMP-03, IMP-09, criterion 3, criterion 5 —
is wrong by one unless the header counts as row 1 (D-26). One exported helper
mints that number, and the dry run, the sample-row stepper and the report all
call it, so the „Zeile 2" on the mapping screen is the same row as the „Zeile 2"
in the report.

Purpose: IMP-09 in full, IMP-03's numbering, and the writer half of IMP-07.
Output: `internal/csv`, standard library only, with a test named after each
defence it holds.
</objective>

**`PruefeBytes(b []byte) error` — the three refusals that happen before parsing
(D-15, IMP-09 empty).** It runs on the raw bytes at stage time, on screen 1,
while the operator is still holding the file, and each refusal is its own
sentinel error so the screen can say which one applies:

- `ErrLeer` — nothing at all was uploaded.
- `ErrNurBOM` — the file is exactly the byte-order mark and nothing else, which
  is what an empty sheet saved from Excel looks like on disk.
- `ErrNullbyte` — the bytes contain `\x00`. Refused and **not cleaned**: a file
  containing a NUL is not a CSV somebody meant to upload, it is a binary file
  with the wrong extension or something worse, and stripping it would hand a
  broken file forward as if it were fine.

**`Zeilennummer(index int) int` — the one place the number is minted (D-26,
IMP-03 boundary).** Exported, three lines, and carrying the longest comment in
the file, because this is the defect that would otherwise be spread across four
screens: the operator reads their spreadsheet, where the header is row 1 and the
first data row is row 2. It is not `stdcsv.Reader`'s record index and it is not
the line number — a quoted cell may span lines and blank lines are skipped, so
line and row are different quantities. `stdcsv.Reader.FieldPos` remains available
if a *line* ever needs naming beside a row; the row is what every requirement in
this phase asks for. The dry run, the sample-row stepper and the report all call
this and none of them adds two of its own.

**The types.**

```
type Zeile struct { Nummer int; Zellen []string; Fehler string }
type Leser struct { … }
```

`Zeile.Nummer` is the spreadsheet's number. `Zeile.Fehler` empty means the row
read cleanly — the same discipline `internal/admin/wordpress.go:107` states for
its own return value, and the discipline this phase keeps even where D-32
replaces the type. A row carrying a `Fehler` still carries whatever cells were
read, so a screen can show the operator what it managed to see.

**`Neu(r io.Reader) (*Leser, error)`.** Wrap the reader in a `bufio.Reader`,
strip a leading BOM **once, here, before the header is read** (D-11) — never at
each later comparison, which is the number-one CSV import bug and the reason the
comment names `plugins/kontaktformular/csv.go:33` as the proof that files
carrying it are the normal case. Then configure the `stdcsv.Reader`:

- `LazyQuotes = true` (D-12), with the reason in the comment: an untrusted upload
  with a stray quote must produce a bad row, not swallow the rest of the file.
- `FieldsPerRecord = -1` (D-13), with its reason: a short row becomes a reported
  row carrying its **row** number instead of an error carrying a line number.
- `ReuseRecord` stays at its default `false`. A caller keeps a `Zeile` after the
  next `Naechste()`, and reusing the backing array would rewrite a row that has
  already been handed out.

Read the header record here and keep it. A reader over a file with no records at
all returns an error the screen can name; a reader over a header with no data
rows is **not** an error — that file is legitimate and IMP-08's empty resolution
is a sentence on the screen, not a refusal.

**`(*Leser) Kopf() []string`**, `(*Leser) Abgeschnitten() bool`, and
**`(*Leser) Naechste() (Zeile, bool)`** — the streaming half, and the reason
`Export.Items` was not copied. `Naechste` reads one record, counts it in our own
counter (D-14 — never from a line number), mints its number with `Zeilennummer`,
pads it out to `len(Kopf())` cells so a short row's missing cells are empty **in
position** rather than shifted (IMP-09 ordering), and checks each cell against
`MaxCellBytes`, setting `Fehler` on the row and naming the offending column when
one is over. A `*stdcsv.ParseError` sets `Fehler` and the loop continues, because
`stdcsv.Reader` can read on past one; any other error stops the reader. Once
`MaxRows` records have been handed out, `Naechste` stops and sets the truncation
flag rather than reading on.

Nothing here formats a sentence for a person. Every message this package produces
is a short technical reason for a developer or an error value; the sentences the
operator reads are minted from reason codes in the template (D-32), and plan
09-03 is where that starts.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| an uploaded file → `internal/csv` | The bytes come from outside the installation. Nothing about their shape, size or encoding may be assumed. |
| a generated example CSV → a spreadsheet program on someone's own machine | A cell beginning `=` is executed by Excel and LibreOffice when the file is opened. |
| `internal/csv` → the rest of the binary | This package's purity is the property later plans rest on; a dependency added here is a dependency every caller inherits. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Denial of Service | `stdcsv.Reader` over an uploaded file | high | mitigate | `encoding/csv` has no bound of any kind. `MaxRows = 5000` and `MaxCellBytes = 100000` are enforced in `Naechste`, both reported rather than silently applied, and both proved at the boundary and one step either side. The byte cap itself is `http.MaxBytesReader` in plan 09-04; the three together are the only reason a 10 MB upload cannot become an unbounded allocation. |
| T-09-02 | Tampering | a NUL byte or a binary file uploaded with a `.csv` extension | medium | mitigate | `PruefeBytes` refuses `\x00` on the raw bytes before parsing, on screen 1, while the operator still holds the file. Refused and not cleaned: stripping it would hand a file forward as if it were fine. |
| T-09-03 | Tampering | CSV formula injection in the generated example file | high | mitigate | `entschaerfen` prefixes an apostrophe to any cell beginning `= + - @ \t \r`, the existing implementation from `plugins/kontaktformular/csv.go:113` copied whole. Both copies name the other, so a fix to one is not silently absent from the other. |
| T-09-04 | Information Disclosure | a parse error naming a line rather than a row | low | mitigate | `FieldsPerRecord = -1` and our own row counter mean a message names the operator's own row number and never an internal line index. Nothing in this package formats a sentence for a person, so no internal detail can reach a screen from here. |
| T-09-05 | Denial of Service | one 9 MB cell inside a legal 10 MB file | high | mitigate | `MaxCellBytes` is checked per cell, per row, in bytes. The row is reported with its number and the reader continues, so one hostile cell costs one row and not the file. |
| T-09-SC | Tampering | npm/pip/cargo/go installs | low | accept | No package-manager install task exists in this plan — every symbol is Go standard library and `go.mod` is untouched. The package-legitimacy gate does not fire and no legitimacy checkpoint is needed. |
