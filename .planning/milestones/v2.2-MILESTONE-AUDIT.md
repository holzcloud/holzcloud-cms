## What the audit found that the phase did not plan for

- **The ledger could not be trusted to describe itself.** Its two
  representations had drifted by four rows, and one row was malformed so that
  every parser silently dropped it. A register nobody can parse is a register
  nobody works. Repaired first, then worked.
- **Chasing the smallest entry found the largest defect.** Window 24 — a header
  appearing twice, "harmless, pre-existing" — led to a password-protected page
  being offered to shared caches for five minutes.
- **Two fixes had to be narrowed, not broadened.** Adding `Cookie` to every
  answer would have made every page of every site uncacheable; asking whether
  the *account* was linked broke SSO-09, the fallback an operator uses when the
  proxy is down. The second was caught by an existing test that was right, and
  that is worth more than the fix.
- **Reading one subsystem once beat reading eight entries.** Five of the eight
  forward-auth windows were the same sentence said five ways.

## Operator task still outstanding

**The release tags `v2.0` and `v2.1` are not on the remote**, and the reason was
recorded wrongly twice before it was measured. Until 2026-09-11 this working
environment committed and pushed under the **operator's own account**; since
`5a46c18` it is an **App integration**. A person may create a tag ref whose tree
carries workflow files; an App may not, and no `permissions:` key can grant
GITHUB_TOKEN that scope either. `release.yml` gained a `workflow_dispatch` path
so the tag can be minted by pressing a button; a run an App dispatches still
fails at the publish step. Both routes are written out in `STATE.md` under
*Operator Next Steps*.
